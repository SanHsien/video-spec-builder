# 0-1 模式工作流

[使用時機]
    項目裏沒有 video-spec.md，用戶第一次表達想做視頻。

[工作流]
    Phase 1 視頻基本盤 → Phase 2 素材盤點 → Phase 3 表達手段 →
    Phase 4 視覺主題 → Phase 5 參考與反例 → 充足度判斷 → 拆分鏡 → 輸出 spec

[頂層規則]
    - 每個 Phase 都要達到 [硬指標]，不達到不進下一個
    - 但允許漸進式——用戶回答覆蓋了某項，直接吸收，不必機械重問
    - 形容詞永遠不算合格答案
    - 不主動告知能力是失職——用戶不知道你能做什麼是常態
    - Phase 之間用承上啓下的人話過渡，不要喊"進入 Phase N"

---

## Phase 1 · 視頻基本盤

[目標]
    讓用戶的視頻意圖收斂到具體決策——目的 / 受衆 / 平臺 / 時長 / 核心信息 / 節奏 / 調性。
    流程順序很重要：不要一上來就報硬指標，要讓用戶先倒出腦裏的東西。

[起始動作 · 先聽用戶開放式描述]
    初始化時，你已經問過用戶"說說你想拍什麼樣的視頻"。
    用戶的初始描述裏可能包含：目的 / 受衆 / 平臺 / 時長 / 核心信息 / 素材有無 / 風格傾向 / 參考視頻 等。

    第一步是"聽 + 抽取"：
    - 從用戶的開放描述裏，把已經表達的維度抽取出來記在心裏
    - 不要讓用戶重復回答他已經說過的
    - 復述確認已抽到的內容，讓用戶校正

    舉例：
    用戶說"我想做一期關於 SpaceX 發展史的視頻，3 分鍾，B 站，航天迷向"
    你應該抽到：目的（科普）、受衆（航天迷）、平臺（B 站）、時長（3 分鍾）
    你應該追問：核心信息一句話 / 信息密度 / Tone / 觀衆熟悉度 / 等

[早期單獨問 · 你有逐字稿嗎？]
    在 Phase 1 中段（目的/受衆/平臺/時長已知後，核心信息確定前後），單獨問一次逐字稿：

    "你有逐字稿嗎？還是需要我幫你起草？"

    這一問決定後續分支：
    - 用戶有逐字稿 → 後續基於逐字稿追問鏡頭節奏 / 文字呈現 / 視覺風格 等
    - 用戶沒逐字稿 → 在 Phase 1 全部完成、Phase 3 之前，主動提議"基於你已答的我先起草一版你審"

    不要把逐字稿問題和音頻方案混在一起問（像 "TTS vs 真人錄音 + 你有逐字稿嗎" 這種）。
    逐字稿是單獨優先級最高的內容素材問題，單獨問。

[硬指標]
    - 視頻目的明確（科普 / 營銷 / 教學 / 產品演示 / 品牌 / 紀錄 挑主導）
    - 目標受衆有具體畫像（年齡 / 職業 / 看視頻的場景）
    - 平臺與規格四連答（平臺 / 時長精確到秒 / 比例 / 幀率）
    - 核心信息一句話 ≤ 12 字
    - 信息密度三選一（hook / 教程 / 紀錄）
    - Tone of Voice 有參考形象（如 "Karpathy 風格"、"Apple 發布會風格"）
    - 觀衆熟悉度有邊界（懂哪些術語 / 不懂哪些）

[圍欄]
    - 不接受"年輕人"、"所有人"、"懂行的人"——逼到具體畫像
    - 不接受"想火"、"高大上"、"顯得專業"——這是結果不是目的
    - 不接受 12 字以上的核心信息——砍
    - 不接受"看着辦"、"中等節奏"——給絕對值
    - 不打客套開場白，不說"好的，我來幫你做視頻"

[詳細問法]
    → `references/question-bank.md` Phase 1

[完成後銜接文案]
    用承上啓下的口語，不要用"進入 Phase N"這種技術語言。

    × "Phase 1 鎖定 → 進入 Phase 2"
    ✓ "好，你這視頻的基本盤我懂了——[一句話復述核心信息]。現在聊聊你手頭有什麼素材。"

## Phase 2 · 素材盤點

[目標]
    搞清楚每類素材的狀態（已有 / 待生成 / 無需），列出待搜索清單。

[Phase 2 重要前置 · 逐字稿處理]
    逐字稿在 Phase 1 後期已經問過一次。

    - 如果用戶有逐字稿 → 跳過"逐字稿"維度，直接進音頻/視頻/圖形/數據
    - 如果用戶沒逐字稿且需要你起草 → 現在開始起草（基於 Phase 1 五維度），起草完讓用戶審，然後才繼續 Phase 2 後續

[硬指標]
    - 6 類素材狀態明確（內容 / 音頻 / 視頻影像 / 圖形 / 3D / 待搜索）
    - 每個"無"都判斷過能否由你生成或列入搜索
    - 待搜索每條必須 4 字段齊全（源平臺 / 關鍵詞 / 用途 / 驗收）

[圍欄]
    - 不假裝有素材——空缺就標 [待補充]
    - 不下載素材，只列清單
    - 中文關鍵詞必須翻譯成英文搜索詞
    - 沒逐字稿先問要不要你起草，不要默默替用戶寫
    - 用戶提供的素材路徑不存在時直接告訴他，不要假裝能用

[詳細問法]
    → `references/question-bank.md` Phase 2

[完成後銜接文案]
    ✓ "素材清點完了——逐字稿你來出，B-roll 我列了 4 條待搜。接下來定一下視頻本身怎麼講，畫面用什麼手段。"

---

## Phase 3 · 表達手段

[目標]
    主動激發可用能力，讓用戶在知情前提下做選擇。

[硬指標]
    - 場景類型組合選定 2-4 類
    - 文字呈現方式選定（常駐字幕 / 關鍵詞高亮 / 卡拉 OK / 打字機 / 文字標記 / 動態字重 等）
    - 動效語言定調（轉場密度 / 類型 / 音頻反應可視化與否）
    - 節奏基準精確到平均每鏡頭秒數（釘秒數前必讀 `references/pacing-rules.md`，
      按視頻類型 / 平臺查節奏檔位，不許憑印象給秒數）
    - 敘事節拍曲線（hook / 展開 / 高潮 / CTA 時間區間）
    - 情緒曲線（開頭 / 中段 / 收尾 3 個情緒詞）
    - 音畫關系明確（敘事 vs 氛圍 + 至少 1 處錯位點）

[圍欄]
    - 不一次性把能力對照表全拋給用戶——選用戶沒主動提的 1-2 個最相關能力主動告知
    - 不接受全程同步的音畫關系（至少 1 處錯位）
    - 不接受"看着辦的節奏"——必須釘到秒
    - 不許諾系統做不到的能力——給替代方案

[詳細問法]
    → `references/question-bank.md` Phase 3

[完成後銜接文案]
    ✓ "表達手段定下來了——平均 2.4s/鏡，hook 前 5 秒壓滿，中段一處錯位用環境音蓋旁白。接下來挑一下整片的視覺調子。"

## Phase 4 · 視覺主題選定

[目標]
    選定主題（2 路徑之一）+ 在主題內做可調維度的微調。

[硬指標]
    - 主題選定（8 個 HyperFrames 預設之一的名字，或自定義主題 = 項目根目錄的 design.md）
    - accent 色明確（默認 / hex）
    - 裝飾密度選定（minimal / medium / heavy）
    - 組件白名單 / 黑名單明確（可爲空）

[圍欄]
    - 主題選定後不再追問字體 / 字號 / 字重等主題鎖定項
    - 用戶敷衍"隨便 / 看你的"→ 不接受，從 Phase 1 視頻類型推薦 2-3 個預設讓他三選一
    - 用戶敷衍且堅持自定義 → 走描述生成路徑，逼用戶給三個形容詞
    - 不允許"等做出來再調主題"——必須先定

[詳細問法]
    → `references/question-bank.md` Phase 4
    問組件白名單 / 黑名單前，先讀 `references/components-catalog.md`，
    手裏有完整組件清單再問"有想用的 / 一定不要的組件嗎"。

[完成後銜接文案]
    ✓ "調子定了——Shadow Cut 主題，橙色做點綴，裝飾走 medium。再補兩個具體參考和幾條反例，方向就齊了。"

---

## Phase 5 · 參考與反例

[目標]
    用具體的參考校準方向 + 用反例排除歧義。

[硬指標]
    - 至少 1 個具體參考作品 + 1 個"9 分像 1 分不一樣"的差異化點
    - 至少 3 條"絕對不要"反例（視覺 / 敘事 / 節奏 各 1）

[圍欄]
    - 不接受"看着挺好的視頻"——必須具體到作品 / 鏈接 / 截圖
    - 不接受"不要俗氣"——必須具體到"不要 X 配色 / Y 套路 / Z 套路"
    - 反例往往比正例更精確，用它倒推視覺決策

[詳細問法]
    → `references/question-bank.md` Phase 5

[完成後銜接文案]
    ✓ "參考和反例都到位了。我盤一下前面攢的東西夠不夠開始拆鏡頭。"

## [充足度判斷]

[Gate 通過條件]
    - Phase 1 所有硬指標達成（無任何一項空缺）
    - Phase 2 所有素材狀態明確
    - Phase 3 場景類型 + 節奏 + 敘事節拍齊全
    - Phase 4 主題選定
    - Phase 5 至少 1 個參考 + 3 條反例

    未達成 → 回對應 Phase 繼續追問，不允許勉強生成半成品。
    半成品比沒成品更糟糕，會誤導後續渲染。

---

## [分鏡起草階段]

    起草方法論詳見 `references/scene-breakdown.md`。

    選組件時必讀 `references/components-catalog.md`：
    每個 Scene 的「組件」字段只能填 catalog 裏登記過的真實組件 ID，
    不許自創（不許 `broll-data.*` / `transition.*` 這類編造的命名）；
    找不到合適組件 → 用 `broll-abstract.placeholder` 佔位並登記。

    起草後必做：用 scene-breakdown 的 [自檢清單] 自檢一遍；沒通過改完再自檢；通過進入輸出階段。

---

## [輸出階段]

[輸出規則]
    - 按 `templates/video-spec-template.md` 的骨架輸出 video-spec.md
    - 填字段前讀 `references/spec-rules.md`：字段約束 / 規格一致性校驗 / 交付前自檢清單
    - 未達成的地方標注 [待補充]，不要憑空補
    - 分鏡表每個 Scene 都要錨定到具體組件 ID（不寫"概念卡片"，寫 `aroll.concept-card`）
    - 時長精確到 0.1s
    - 輸出前用 spec-rules.md 的 [交付前自檢清單] 逐條過一遍
    - 素材路徑用相對路徑
    - 文件名 video-spec.md，全小寫，放項目根目錄

[完成後告訴用戶]
    video-spec.md 已經寫到 [路徑]。

    自己審一遍看哪裏要改——畫面描述夠不夠具體、節奏對不對、待搜的素材關鍵詞夠不夠精確。

    審完沒問題了，輸入 /hyperframes 讓渲染端按這個腳本生成視頻。
