# Video Spec 填寫規則

`templates/video-spec-template.md` 是要填的骨架，本文件是每個字段的約束、規格一致性校驗、和輸出前的自檢清單。

通用原則：

- 時間精度統一到 0.1s
- 每個分鏡的「組件」ID 必須來自 `components-catalog.md` 登記的真實 ID，不許自創
- 只把用戶明確說過的寫進 spec；推斷的內容標 `[待用戶確認]`，純空缺標 `[待補充]`，不憑空補

---

## 規格一致性校驗

§ 1 視頻基本盤和 § 4 視覺規範裏的規格，任一項不一致 → 直接報錯回去修，不要輸出。

- 平臺是 YouTube Shorts / 抖音 / TikTok / 小紅書 / 視頻號 → 畫面比例必須 9:16
- 平臺是 YouTube 長視頻 / B 站 / 發布會大屏 → 畫面比例必須 16:9
- 平臺是 X / LinkedIn → 畫面比例 1:1 或 16:9
- 平臺是產品官網 / Demo / 內部 → 通常 16:9
- 時長與信息密度匹配：抓眼球型默認 ≤ 60s / 講清楚型 30s-5min / 沉浸型 ≥ 60s
- 視覺主題必填，2 選 1（預設或自定義），不能空
- accent 色不改寫默認；改就給具體 hex，不接受「品牌色」「和 logo 一樣」
- 畫質：草稿 / review 階段填 standard，最終交付填 high（high 渲染耗時約翻倍）

## 各節字段約束

### § 1 視頻基本盤
- 目的 / 受衆 / 核心信息 每項不允許敷衍形容詞
- 觀衆熟悉度必須給術語邊界，不接受「都看得懂」
- 語氣基調給具體參考形象，不接受「專業 / 高大上」
- 核心信息 ≤ 12 字，能被剪成大字海報標題

### § 2 敘事結構
- 敘事節拍各段時間區間加起來 = 全片總時長
- 情緒曲線 3 個詞必須有變化方向，不接受「好看 / 值」
- 音畫關系至少 1 處錯位點，不接受「全程同步」
- 同質化反例至少 3 條（視覺 / 敘事 / 節奏 各 1）

### § 3 表達手段
- 場景類型 3-5 種，按出現順序列
- 社媒短視頻（YouTube Shorts / 抖音 / TikTok / 小紅書 / 視頻號）默認必選「卡拉 OK 逐詞」字幕
- 3D / shader / 音頻反應 每項要明確要不要，要就必有描述
- 節奏基準與信息密度一致

### § 4 視覺規範
- 只能調 4 個維度：accent 色 / 裝飾密度 / 組件白名單 / 組件黑名單
- 主題鎖定的維度（背景 / 字號 / 字體 / 字重 / 動效曲線 / 圓角間距）不在這裏覆蓋，要改就換主題
- 不寫具體 px / ms / 字號數值

### § 5 素材清單
- 已有素材必有具體路徑；路徑不存在直接說，不假裝能用
- 待生成素材必寫生成方式（voice ID / 速率 / 源文件）
- 待搜索素材 4 項（源平臺 / 關鍵詞 / 用途 / 驗收標準）缺一不可
- 關鍵詞具體可搜，中文模糊詞翻譯成英文，不寫「好看 / 有質感」

### § 6 分鏡表（重點）

字段約束：

- **時間**：起止秒，精度 0.1s，禁用「大概 3 秒 / 短暫停頓」
- **類型**：A-roll（主線講解）/ B-roll（輔助鏡頭）/ 轉場（獨立成鏡的過場如反白閃屏）
- **組件**：必須是 components-catalog.md 登記過的 ID；找不到 → `broll-abstract.placeholder` 佔位 + 在 § 9 登記
- **旁白文案 vs 屏顯文案**：哪怕內容一樣也分開寫（一個是聽到的、一個是看到的）
- **期待內容**：這一鏡傳達的具體信息（數據 / 概念 / 情緒 / 動作），不接受空話
- **期待效果**：觀衆該產生的反應，不接受「好看 / 高級」
- **畫面描述**：鏡頭裏有什麼、布局如何、是否 3D、9:16 還是 16:9 適配——所有視覺維度都要落進來
- **動效要點**：動詞級（SLAMS / CASCADE / FLOATS / DRAWS），不寫 ms / ease 參數
- **音效描述**：每個 Scene 都要寫——無音效寫「無」
- **轉場**：進入 + 離開必填，「硬切」是合法轉場也必須明寫
- **素材依賴**：Scene 用到的具體素材都列出

特殊規則：

- 反白閃屏全片 ≤ 2 次，兩次間隔 ≥ 8s；第 2 次起在畫面描述裏注明「第 N 次反白閃屏（剩 N 次）」
- 末鏡是唯一允許 exit 動畫（fade-out 到黑）的 Scene，其他 Scene 只寫 entrance
- 9:16 豎屏布局：三列變三行 / 字幕區域上移 / 最大寬度收窄 / 大字收窄到畫面 60% 寬——畫面描述必須考慮
- A-roll 必須有完整旁白原文（字幕逐詞高亮，省略號不行）
- 同一組件全片用 ≥ 4 次 → 視覺單調警告，考慮換組件
- 過場（bridge）鏡頭佔比 ≤ 15%
- hook 鏡頭必須落在視頻開頭 3s 內至少 1 個

### § 7 音頻時間軸
- TTS 旁白寫清「用 [voice ID] [Nx 速率] 從 [script 文件] 生成」
- BGM volume 通常 0.15-0.25，旁白同時存在時 ducking 到 0.1-0.15
- 音效時間碼必須能在 § 6 分鏡表找到對應觸發點
- BGM 起止時間 = 視頻總時長

### § 8 參考與反例
- 至少 1 個正向參考 + 1 個差異化點
- 至少 1 個反例 + 3 條「絕對不要」（視覺 / 敘事 / 節奏 各 1）
- 不接受「都好看 / 都不像」

### § 9 開放問題
- 字段路徑寫法：`節名 / 子項`——一級用節標題（不帶編號），二級用字段名，Scene 用 `Scene NN` 兩位補零
- 示例：`視頻基本盤 / 核心信息` · `Scene 03 / 畫面描述` · `音頻時間軸 / 背景音樂`
- 無開放問題寫「無，spec 已完整」

## 交付前自檢清單

輸出 video-spec.md 前逐條過一遍：

- [ ] 正文第一句是「請你按照以下 script，幫我生成一條視頻……」
- [ ] § 1 視頻基本盤字段全填，不知道的寫 `[待補充]`，不留空
- [ ] 規格一致性校驗全過（見上）
- [ ] 受衆畫像具體到職業 + 痛點，核心信息 ≤ 12 字
- [ ] § 6 每個 Scene 12 字段全填，「畫面描述 / 音效描述 / 期待內容 / 期待效果」無一省略
- [ ] 每個 Scene 時間精度 0.1s；組件 ID 真實、無自創
- [ ] 每個 Scene 轉場進入 + 離開都寫了，「硬切」也明寫
- [ ] 動效字段只寫動詞，不寫 ms / ease 參數
- [ ] 旁白文案與屏顯文案分開寫，哪怕內容相同
- [ ] 反白閃屏全片 ≤ 2 次、間隔 ≥ 8s；末鏡是唯一允許 exit 動畫的 Scene
- [ ] 9:16 豎屏的布局差異已落進每個 Scene 的畫面描述
- [ ] § 7 音效時間碼能在 § 6 找到觸發點，BGM 起止時間 = 視頻總時長
- [ ] 節奏檔位與信息密度匹配、總時長誤差 ≤ ±0.5s（詳見 `pacing-rules.md`）
