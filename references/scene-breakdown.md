# 分鏡拆解方法論

[使用時機]
    - 0-1 模式 Phase 1-5 都問完後，進入分鏡起草階段
    - 迭代模式加新場景 / 大段重排時

[核心理念]
    分鏡 = 把腳本翻譯成可執行的畫面 + 動效，不是切段落。
    每個 Scene 必須回答 4 個問題：
    1. 信息載荷 —— 這一鏡讓觀衆 get 到什麼？
    2. 組件 ID —— 用 components-catalog 哪個組件承載？
    3. 時長 —— 幾秒？
    4. 轉場 —— 怎麼進、怎麼出？

---

## [輸入]

[輸入形態]

    1. 逐字稿（最理想）
        已有完整旁白文本，按句號 / 語意單元切分

    2. 賣點列表
        3-7 個要點，每點要單獨鏡頭表達

    3. 大綱
        三幕結構（開-中-收），每幕有粗略要點

    4. 都沒有
        基於核心信息 + 受衆 + 時長，你寫草稿（前置：Phase 1 五維度齊全）

[輸入校驗]
    每種輸入都必須能回答：
    - 總時長（來自 Phase 1）
    - 信息密度檔位（hook / 教程 / 紀錄）
    - 核心信息（≤ 12 字）
    - 敘事結構（來自 Phase 3.5 / 3.6 / 3.7）：
      節拍曲線 + 情緒曲線 + 音畫關系 + 同質化反例
      → 拆分鏡前必須先讀 video-spec.md 的 [敘事結構] 章節
      → 每個 Scene 都要落到節拍曲線的某一段

## [六步法]

### [一、內容分割]

    [逐字稿]
        1. 按句號斷句 → 候選鏡頭列表
        2. 合並連續短句（< 8 字）→ 節奏鏡頭
            例："來。看這個。這就是答案。" → 合並爲 1 鏡，但保留 3 段動效層級
        3. 長句（> 30 字）拆成多鏡頭
            拆分點：連詞（但是 / 因爲 / 所以）/ 轉折標記 / 數據出現處
        4. 排比句 / 列舉句 → 每項獨立鏡頭（視覺上做"序列感"）

    [賣點列表]
        每個賣點拆成：
        - 1 個核心鏡頭（陳述賣點）
        - 0-2 個支撐鏡頭（證據 / 數據 / 演示）
        - 總數控制：3-7 個賣點 × 平均 2 鏡 = 6-14 個 Scene

    [大綱]
        三段分配：
        - 開（hook）：1-3 鏡頭，佔 15-20%（30s 視頻 → 5-6s 內 / 60s → 10-12s 內）
        - 中（核心）：5-15 鏡頭，佔 60-70%（主要信息密度區，節奏快-慢交替）
        - 收（cta / 收束）：1-2 鏡頭，佔 10-15%（收束核心信息 + 可選 CTA）

    [都沒有]
        你根據 Phase 1 五維度起草大綱：
        - 推算鏡頭總數（按節奏類型 × 總時長 → 大致鏡頭數）
        - 起草大綱三段
        - 必須讓用戶確認大綱再繼續拆細
        - 不要從零跳到逐字稿——中間要有大綱校準

### [二、節奏分配]

    [按節奏類型分配時長基準]

        - hook 型（每鏡 0.8-2s 主，關鍵鏡頭 2-3s）
        - 教程型（每鏡 2-5s 主，關鍵解釋 5-7s）
        - 紀錄型（每鏡 3-8s 主，強調鏡頭 6-10s）

        詳細分配見 pacing-rules.md。

    [總時長校驗]
        - 所有鏡頭時長 + 轉場時長（粗略） ≈ 用戶設定的總時長
        - 轉場粗估 0.2-0.5s/轉場（精確值後續渲染時定）
        - 誤差 ±0.5s 以內允許

    [節奏曲線紀律]
        - 不允許"全片均速"——會讓觀衆疲勞
        - 推薦節奏曲線：快-快-慢-快-慢-慢-快收尾
        - 關鍵信息鏡頭前一鏡可以加快（制造對比，凸顯關鍵鏡頭的"停頓感"）

### [三、鏡頭打標]

    [標籤集合（一鏡可多標籤）]

        - `[hook]` 抓注意力（開頭 / 大轉折 / 反差衝擊）
        - `[data]` 數據 / 統計 / 排名
        - `[concept]` 概念 / 定義 / 抽象闡釋
        - `[emotion]` 情緒 / 價值觀 / 故事感
        - `[demo]` 演示 / 操作 / 產品功能
        - `[versus]` 對比 / 反差 / A vs B
        - `[structure]` 結構 / 層級 / 分類
        - `[flow]` 流程 / 步驟 / 序列
        - `[cta]` 行動召喚 / 引導動作
        - `[bridge]` 過渡 / 橋接（不承載主信息，但連接兩段）
        - `[summary]` 總結 / 收束 / 重申核心信息

    [打標紀律]
        - 每個 Scene 至少 1 個主標籤 + 0-2 個副標籤
        - `[bridge]` 佔比 ≤ 15%（橋接太多會稀釋信息密度）
        - `[hook]` 標籤的鏡頭必須落在視頻開頭 3s 內（至少 1 個）
        - 一個 Scene 同時具備 `[data] + [concept]` → 警告"信息復合度高，注意信息過載"

### [四、組件匹配]

    [按標籤 + 內容性質從 components-catalog 選組件]

    | 標籤 | 優先匹配 |
    |------|---------|
    | hook | broll-hero.big-type / broll-hero.inversion-flash / aroll.subtitle-highlight |
    | data | broll-charts.* / broll-hero.big-number |
    | concept | broll-abstract.* / aroll.concept-card |
    | emotion | broll-hero.pull-quote |
    | demo | broll-ui.* / 真人 + aroll |
    | versus | broll-abstract.versus / broll-abstract.spectrum |
    | structure | broll-structure.* / broll-structures2.* |
    | flow | broll-flows.* |
    | cta | broll-hero.big-type |
    | bridge | broll-hero.inversion-flash（注意 ≤2 次）|
    | summary | broll-hero.pull-quote / aroll.subtitle-highlight |

    [組件匹配紀律]
        - 不允許"自創組件"——必須落到 components-catalog 已有 ID
        - 某 Scene 沒有合適組件 → 重寫文案 / 改標籤，不要發明組件
        - 同一組件全片用 ≥ 4 次 → 警告"視覺單調"
        - 同一類組件（如 broll-charts.*）用 ≥ 5 次 → 警告"圖表過密集"

    [詳細清單]
        見 components-catalog.md（含每個組件的適用場景 / 何時不用 / 內容期待）。

### [五、轉場決策]

    每個 Scene 都要明確"轉場進入"和"轉場離開"，只寫類型，不寫參數。
    不允許 jump cut。

    轉場類型（4 種粗粒度）：
    - 硬切（hard cut）—— 默認，瞬間切換
    - 軟切（crossfade）—— 柔和過渡
    - 反白閃屏 —— 硬規則：≤ 2 次/視頻，間隔 ≥ 8s
    - shader 轉場 —— 僅寫"shader 轉場"，具體效果後續選

    具體 ease / duration / shader ID 由視覺富化階段決定。

### [六、素材綁定]

    [每鏡必須綁定的素材]

        - 旁白文案
            - 從逐字稿對應段落抽取
            - 如無逐字稿，你根據 Scene 主題 + 屏顯文案補
            - 用 TTS → 在素材依賴裏標 "voice/scene-XX.mp3"

        - 屏顯文案
            - 旁白的關鍵詞（不是全文！）
            - 12 字以內的核心句
            - 高亮詞單獨標記

        - 素材依賴
            標注需要的：圖片（路徑）/ 視頻（路徑 + 時長 + 起始偏移）/
            數據文件（data.json）/ Lottie / 3D 模型（路徑 + camera 參數）/ 非默認字體

        - 缺素材的鏡頭
            標記 `[待補充素材]` + 退化方案
            例：`[待補充素材] 真人產品演示視頻；退化方案：用 broll-ui.browser 模擬產品界面`

    [素材綁定紀律]
        - 不允許"過度樂觀"——沒素材就標待補充，不要默認你能生成
        - 素材路徑用相對路徑（./assets/xxx）
        - 同一素材在多 Scene 復用 → 明確標注 "復用自 Scene XX"

## [輸出格式]

[每鏡必填字段]
    嚴格對齊 templates/video-spec-template.md「Script · 分鏡表」節的字段，順序不變：

    標題行：Scene NN · [start]s – [end]s · [節拍標籤，如 hook / 反差 / 數據 / 高潮 / CTA]

    11 個內容字段：
        1.  類型（A-roll / B-roll / 轉場）
        2.  組件（來自 components-catalog.md 的真實 ID）
        3.  旁白文案（完整原文 / —）
        4.  屏顯文案（屏幕顯示的文字 / —）
        5.  期待內容（本鏡傳達的內容 / 數據 / 概念 / 情緒）
        6.  期待效果（觀衆應該產生的反應：震撼 / 理解 / 記住 / 笑 / 共鳴）
        7.  畫面描述（鏡頭裏有什麼、布局、是否 3D、關鍵視覺要素）
        8.  動效要點（動詞級，如 SLAMS / CASCADE / floats）
        9.  音效描述（無音效寫「無」；有寫具體類型 + 時間點）
        10. 轉場進入 + 轉場離開（類型級：硬切 / crossfade / shader / 反白閃屏）
        11. 素材依賴（narration.wav 段 / bgm.mp3 / 待搜索 X / 已有素材 Y）

[Scene 排版]

```
Scene XX  [start-end / duration]  · [節拍標籤]
├─ 類型：A-roll / B-roll / 轉場
├─ 組件 ID：broll-hero.big-number
├─ 旁白文案：…
├─ 屏顯文案：…（含高亮詞標記）
├─ [期待內容]：本鏡要傳達的具體內容（數據/概念/情緒/動作）
├─ [期待效果]：本鏡應該讓觀衆產生什麼反應（震撼/理解/記住/笑/共鳴）
├─ 畫面描述：（畫面構成 / 布局 / 是否 3D / 裝飾層）
├─ 動效要點：（關鍵入場 / 出場 / 內部動效，動詞級）
├─ 音效描述：（無 / 具體類型 + 時間點，如「3.0s · 短促 click，volume 0.3」）
├─ 轉場進入 ← / 轉場離開 →
└─ 素材依賴：（路徑 / [待補充素材]）
```

[期待內容] 和 [期待效果] 是產品需求——渲染時按這兩個字段調整視覺強度、節奏、裝飾層。
[音效描述] 字段不能省，無音效也要明寫「無」，避免輸出時被遺漏。

[動效要點]
    只寫動詞級別（choreography verbs），不寫具體動效參數。
    常用動詞：SLAMS / CASCADE / FLOATS / WHIPS / DISSOLVES / PULSES / SPIRALS / SCRATCHES。

    合格："title SLAMS 入場 + subtitle CASCADE 錯峯"
    反例："y 30→0, 700ms ease power3.out"（這是視覺富化的活兒）

    具體 ease / duration / 物理參數後續富化時再寫。

## [自檢清單]

[輸出後逐項檢查]

```
□ 每個 Scene 都錨定到 components-catalog 裏的組件 ID（沒有自創）
□ 總時長 = 所有 Scene 時長 + 轉場時長（誤差 ±0.5s 以內）
□ 反白閃屏 ≤ 2 次（全片硬上限）
□ Shader 轉場使用頻率 ≤ 1/3 Scene
□ 每 Scene 都明確寫出轉場進入和離開
□ 沒有 jump cut（無轉場切換）
□ A-roll 字幕高亮的鏡頭有完整的旁白文本
□ 數據圖表 Scene 標注了數據來源（data.json 或 inline）
□ 用了真人出鏡組件的 Scene 標注了視頻路徑和是否需要摳像
□ 每個組件的"何時不用"原則沒被違反（參考 components-catalog）
□ hook 鏡頭落在視頻開頭 3s 內
□ 同一組件全片使用 ≤ 4 次（視覺變化保證）
□ [bridge] 標籤鏡頭佔比 ≤ 15%
□ 節奏曲線不是均速（有快慢對比）
□ 收尾鏡頭有明確的結束方式（淡出 / 靜幀 / CTA 停留）
□ 缺素材的 Scene 標了 [待補充素材] 和退化方案
□ 旁白文案的總字數與總時長匹配（按 3-4 字/秒估算）
□ 所有屏顯文案 ≤ 12 字（hero 句）或 ≤ 8 字（關鍵詞）
□ 每個 Scene 都有信息載荷（不存在空幀）
□ 每個 Scene 都明確寫了 [期待內容]（要傳達的具體信息）
□ 每個 Scene 都明確寫了 [期待效果]（觀衆應該產生的反應）
□ 每個 Scene 都明確寫了 [畫面描述]（含布局 + 是否 3D）
□ 每個 Scene 都明確寫了 [音效描述]（無音效就寫「無」，不能省）
□ 動效要點只寫動詞級（SLAMS / CASCADE / FLOATS 等），不寫 GSAP 參數
□ 轉場字段只寫類型（硬切 / 軟切 / 反白閃屏 / shader），不寫 duration / ease
```

## [常見陷阱]

[陷阱 1：按句號切完就當分鏡]
    問題：句號不等於視覺切點
    應對：再過一遍，看哪些短句要合並，哪些長句要拆分

[陷阱 2：每個 Scene 都用大字 hero]
    問題：視覺單調，觀衆疲勞
    應對：組件多樣性自檢——同一組件 ≤ 4 次

[陷阱 3：轉場字段寫具體參數 / 全用同一種]
    問題：寫出 "crossfade 300ms ease-out" → 越界
    應對：只寫類型（硬切 / 軟切 / 反白閃屏 / shader）

[陷阱 4：反白閃屏每個 Scene 都用]
    問題：違反 hard rule（≤ 2 次）
    應對：留給最關鍵的兩個轉折點（一般在 hook 進入 + 數據高潮）

[陷阱 5：節奏全片均速]
    問題：觀衆沒記憶點，所有鏡頭一樣長
    應對：檢查節奏曲線，必須有快慢對比

[陷阱 6：所有 Scene 都堆滿信息]
    問題：信息密度過載，觀衆消化不了
    應對：穿插 [bridge] 或 [emotion] 鏡頭給觀衆喘息（但佔比 ≤ 15%）

[陷阱 7：忘記給數據 Scene 標數據源]
    問題：渲染時無數據可用
    應對：data Scene 必須標 data.json 路徑或 inline 數據

[陷阱 8：A-roll Scene 旁白不全]
    問題：字幕高亮無法精確同步
    應對：A-roll 必須有完整旁白文本（不能用"省略號"）
