# 節奏規範

[使用時機]
    - 選定信息密度後（Phase 1.5）
    - 分配每個 Scene 時長時
    - 決定轉場密度時
    - 校驗總時長時
    - 判斷 hook 鏡頭是否合格時

[核心命題]
    節奏不是"感覺"，是每秒承載多少信息的數學問題。
    - 高密度 = 每秒一個信息點
    - 低密度 = 每 5-8 秒一個信息點 + 中間用情緒填充
    - 節奏 ↔ 平臺 互相約束（抖音不允許慢節奏，發布會不允許 hook 型）

---

## [三檔節奏]

按主導節奏給出每鏡頭時長 / 每分鍾鏡頭數 / 轉場頻率 / 留白比例。

```
[hook 型 · 高密度]
    適用：短視頻開頭 / 抖音 / 廣告 / 產品發布
    每鏡頭：0.8 - 2.0s
    每分鍾鏡頭數：30 - 60
    大轉場頻率：每 4-6s 一次
    留白：< 5%
    旁白字數：≈ 1.5-2 字/秒（60s ≈ 90-130 字）
    典型應用：YouTube Shorts 30s · TikTok 15s · 信息流廣告 6s
    音頻：BGM 必須有強節拍，每鏡頭切換對應一個 beat

[教程型 · 中等密度]
    適用：科普 / 教程 / 產品演示 / B 站知識區
    每鏡頭：2.0 - 5.0s
    每分鍾鏡頭數：15 - 30
    大轉場頻率：每 10-15s 一次
    留白：10-15%
    旁白字數：≈ 2-3 字/秒（3min ≈ 400-550 字）
    典型應用：B 站知識區 3-5min · 教程視頻 · 產品演示 60-90s
    音頻：BGM 偏柔，旁白爲主，關鍵節點留呼吸感

[紀錄型 · 慢節奏]
    適用：vlog / 紀錄片 / 品牌片 / 慢敘事
    每鏡頭：3.0 - 8.0s
    每分鍾鏡頭數：8 - 15
    大轉場頻率：每 20-30s 一次
    留白：20-30%
    旁白字數：≈ 1.5-2.5 字/秒（90s ≈ 140-220 字，可大段無旁白）
    典型應用：品牌片 90s · 紀錄片 5min+ · 電影預告 60-120s
    音頻：氛圍樂 / 情緒音 / 旁白慢語速 / 留白
```

[Rhythm 命名]
    具體 rhythm pattern（如 fast-fast-SLOW / hook-PUNCH-hold-CTA）後續視覺富化階段定。
    本文件只管時長基準 + 總時長校驗。

## [總時長校驗]

按目標時長反推鏡頭數 + 轉場密度。

| 時長 | 鏡頭數 | 大轉場 | 反白閃屏 | hook 時點 | 典型場景 |
|---|---|---|---|---|---|
| < 3s | — | — | — | — | 拒做（信息載荷不夠） |
| 3-5s | 1-2 | 0 | 0 | 全鏡即 hook | 微視頻封面 / 極短廣告 |
| 5-10s | 3-7 | 0-1 | ≤ 1 | 全片即 hook | 抖音封面 / Twitter / Story |
| 15-20s | 8-15 | 1-3 | ≤ 1 | 開頭 3s | 抖音單條 / 信息流廣告 |
| 30s | 12-25 | 2-4 | ≤ 2 | 開頭 3-5s + 結尾 2-3s CTA | 抖音長版 / 產品宣傳 |
| 60-90s | 18-40 | 3-6 | ≤ 2 | 中段允許小章節切換 | 發布會片頭 / 品牌片 / Vlog |
| 3-5min | 50-150 | 6-12 | 章節卡分隔 | 每 30-45s 一次節奏重置 | YouTube / B 站知識區 |
| 5-10min | 90-300 | 12-30 | 章節卡分隔 | 每章節獨立 hook | YouTube 長視頻 / B 站深度 |
| 10-30min | 拆 spec | — | — | 每 episode 獨立 hook | 拆爲 2-4 個獨立 spec |
| ≥ 30min | 拆系列 | — | — | — | 不在單 spec 範圍內 |

[平臺對照]

| 平臺 | 節奏類型 | 每鏡頭時長 | hook 時點 | 畫幅 |
|---|---|---|---|---|
| 抖音 / TikTok | hook 型 | 0.8-2s | 前 3s（強制字幕） | 9:16 |
| YouTube Shorts | hook 型 | 1-2.5s | 前 3s | 9:16 |
| YouTube 主頻道 | 教程型 | 2.5-5s | 前 15s（章節標記） | 16:9 |
| B 站知識區 | 教程型 | 2-4s | 前 10s（章節卡） | 16:9 |
| 發布會大屏 | 紀錄型 | 3-8s | 前 5s（建立氛圍） | 16:9 |
| 品牌官網 hero | loop 友好 | 5-15s | 首尾幀相似 | 16:9 |

[時長推算公式]
    鏡頭數 N = 總時長 T ÷ 平均鏡頭時長
    轉場總時長 ≈ N × 0.2-0.5s（粗估）
    實際鏡頭總時長 = T − 轉場總時長
    誤差 ±0.5s 允許。

    舉例：
    - hook 型 30s → N ≈ 30/1.5 ≈ 20 鏡，轉場佔用 2-3s
    - 教程型 3min → N ≈ 180/3.5 ≈ 51 鏡，轉場佔用 8-10s
    - 紀錄型 90s → N ≈ 90/5 ≈ 18 鏡，轉場佔用 5-8s

## [Hook 鏡頭]

第一鏡決定用戶停留還是滑走，是整支視頻最貴的鏡頭。

```
[第一鏡定生死]
    - 0-3s 內必須建立"看下去的理由"
    - hook 鏡頭時長 ≤ 2s（短平快）
    - 必須有強視覺刺激：大字 / 數字 / 強反差 / 轉場閃屏
    - 不允許第一鏡是"安靜的標題卡"
    - 不允許 logo 單獨佔第一鏡（logo 是片尾，不是 hook）
    - 不允許"黑屏 + 漸入文字"超過 1s（除非是極端慢敘事）

[hook 推薦組件]
    1. broll-hero.big-type        文字 hook
    2. broll-hero.big-number      數據 hook
    3. broll-hero.inversion-flash 視覺切入
    4. aroll.subtitle-highlight   口語 hook
    5. broll-charts.bar-chart     數據反差 hook

[hook 反例]
    × 第一鏡放品牌 logo 漸入 3 秒
    × 第一鏡放黑屏 + "故事開始於一個夜晚..."
    × 第一鏡放主持人自我介紹
    × 第一鏡放安靜的產品圖（除非是奢侈品片）
```

## [轉場密度]

轉場不是裝飾，是節奏的換氣符號。用錯了眩暈，用少了平。

```
[硬切 / 軟轉 / 大轉場比例]
    - 80% 硬切（場景之間瞬切）
    - 15% 軟轉（B-roll 之間）
    - 5% 大轉場（反白閃屏 / shader / wipe，章節切換專用）
    具體 crossfade / shader duration 後續視覺富化階段定。

[反白閃屏紀律]
    - 每支視頻 ≤ 2 次（硬規則）
    - 不允許連續使用（間隔 ≥ 8s）
    - 用於"章節切換"或"修辭停頓"，不用作日常切換
    - 反白瞬間不允許有內容（純白屏即可）

[同組件連續切換]
    例：連續 3 個 broll-charts.bar-chart 展示季度數據
    - 用軟切 + 組件自帶 stagger 讓數據變化看起來連貫
    - 不要每次都"重新出現一個新圖表"
    - 讓組件框架不變、內部數據更新，類似 dashboard 切換

[shader 轉場紀律]
    - 僅用於節奏巨大轉折點（hook → 主體 / 主體 → 高潮 / 高潮 → 收尾）
    - 每支視頻 ≤ 1 次（30s 以下）或 ≤ 2 次（60s 以上）
    - shader 風格要匹配視頻調性（液態/像素/分形 vs 極簡風衝突）
    - 具體 shader ID 後續視覺富化階段定
```

## [信息密度]

判斷每個 Scene 能不能存在的核心標準。

```
[每個 Scene 的信息承載]
    - hook 型：1 個核心信息 + 0 個支撐信息（專注一擊）
    - 教程型：1 個核心信息 + 1-2 個支撐信息（標題 + 1-2 個細節）
    - 紀錄型：1 個核心信息 + 0-1 個氛圍信息

[禁止空幀]
    - 每個 Scene 都必須承載至少 1 個信息
    - 不允許"過渡黑屏 3 秒"（除非是 hook 前的懸念，最多 0.5s）
    - 留白要承載"喘息"而非"等待"
    - 用戶說"這裏安靜一下" → 追問"安靜要承載什麼？靜默是一種信息，不是空白"

[文字密度]
    - 每屏文字 ≤ 12 字（中文）或 ≤ 8 詞（英文）
    - 引用塊例外，可到 30 字 / 20 詞
    - 數據圖表的標籤除外
    - 超限 → 拆成兩個鏡頭 + crossfade

[數據密度]
    - 單屏數據 ≤ 3 個數字（hook 鏡頭 ≤ 1 個大數字）
    - 圖表軸標籤 ≤ 7 個
    - 表格 ≤ 5 行 × 4 列（超出拆成多鏡頭）
```

## [微視頻策略 · ≤ 10s]

抖音封面、Twitter 短帖、Story / Reels 封面、信息流 hover 等場景。
極短時長意味着信息載荷必須收斂到 1-2 個點，否則觀衆消化不動。

```
[時長決策]
    - < 3s：拒做。告訴用戶改用靜圖或加長到 5s+
    - 3-5s：單鏡或雙鏡，每鏡 2-3s。純 hero 大字 / 數據衝擊。hook 即全部
    - 5-10s：hook 型，每鏡 0.8-1.5s，3-7 鏡。hook + 小展開 + 收尾大字

[追加要求]
    - 結構 = hook + CTA（或 hook + hero takeaway），不分"展開/高潮"
    - 反白閃屏 ≤ 1 次（5s 內 2 次過密，眼睛喫不消）
    - 文字密度 ≤ 8 字/屏（停留時間短，超 8 字讀不完）
    - 旁白控制：
        - ≤ 5s：無旁白，純視覺 + 大字
        - 5-10s：≤ 25 字旁白，或純字幕無旁白
    - 必須無聲友好（靜音狀態下用戶也能 get 到信息）
    - 必須有強視覺刺激（大字 / 大數字 / 強反差 / 反白閃屏，4 選 1）

[反例]
    × 5s 視頻塞 3 段旁白 → 旁白未完用戶已劃走
    × 8s 視頻用 4 個 1.5s 鏡頭講 4 件事 → 信息過載，1 個也記不住
    × 3s 視頻用淡入淡出 → 轉場喫掉 1s，浪費 1/3 時長
```

## [長視頻策略 · ≥ 5min]

長視頻拆 episode（章節），不要單 spec 寫完一坨。
拆章節帶來：每章節獨立 hook（重復抓回觀衆）+ 節奏 reset 點（快慢交替更明顯）+ 渲染失敗可獨立重做。

```
[時長決策]
    - ≤ 5min：單 spec 完整覆蓋
    - 5-10min：單 spec，分鏡表必須分 3-5 章節（每章節有獨立節拍 + 高潮點）
    - 10-30min：拆成 2-4 個獨立 spec（每個 5-10min），用 episode 信息串起
        - 每個 spec 在 § 1 視頻基本盤注明「episode 1/4 · 系列名 <series-name>」
        - 各 episode 獨立可渲染，但共用主題 / accent / 組件白名單
    - ≥ 30min：建議拆系列視頻（不在單 spec 範圍內），先做 trailer + 第一集

[追加要求]
    - 每章節獨立 hook（每 60-90s 重復抓回觀衆，否則注意力流失）
    - 每章節有節奏 reset 點（章節內快-慢交替更明顯，不允許全章節同速）
    - 章節之間用 shader 轉場或反白閃屏作章節卡分隔（章節卡內有章節編號 + 標題）
    - 總鏡頭數 = 60-180 個（5-10min 區間），按 2-4s/鏡均速估算
    - 章節間用 timeline-row 或 chapter-marker 做"目前進度"提示（強信息流場景必加）
    - BGM 必須有 2-3 個 motif 切換（不能 5min 同一段循環 30 遍）

[章節結構推薦]
    - 總覽 hook（5-10%）：拋出整片要解決的問題
    - 章節 1（25%）：第一個論點 + 論據 + 小高潮
    - 章節 2（25%）：第二個論點 + 論據 + 小高潮
    - 章節 3（25%）：第三個論點 / 反轉 / 綜合
    - 收束 CTA（10-15%）：復述核心 takeaway + 行動召喚

[反例]
    × 8min 視頻從頭到尾沒有章節卡 → 觀衆 3min 就走神
    × 章節都是相同節奏（3s/鏡）→ 沒有 reset 點，觀衆疲勞
    × BGM 一首循環到底 → 聽覺單調
```

## [節奏校驗自檢]

生成 video-spec.md 之前必須過一遍。

```
□ 第一鏡在 2s 內（hook 型）/ 5s 內（教程型）/ 8s 內（紀錄型）
□ 總鏡頭數符合節奏類型基準
□ 反白閃屏 ≤ 2 次且不連續
□ shader 轉場 ≤ 2 次
□ 沒有空幀（除 < 0.5s 懸念）
□ 文字密度 ≤ 12 字/屏
□ 每個 Scene 都承載至少 1 個信息
□ 轉場比例：80% 硬切 / 15% 軟轉 / 5% 大轉場
□ 總時長 = Σ鏡頭時長 + Σ轉場時長（誤差 ±0.5s）
□ 節奏類型與平臺匹配（抖音不允許慢節奏，發布會不允許 hook 型）
□ hook 鏡頭有強視覺刺激
□ CTA 鏡頭時長 2-3s（不超不少）
□ 中長視頻（≥ 60s）有節奏重置點
```

## [常見錯誤]

```
[第一鏡慢入]
    診斷：第一鏡超過 2s 還沒有視覺衝擊
    修正：換成 hook 推薦組件中的任一個，或把節奏從 hook 改爲慢節奏（僅當不是社媒平臺）

[連續反白閃屏]
    診斷：兩次反白閃屏間隔 < 8s
    修正：保留一次，把另一次改爲硬切或 crossfade

[總時長不對]
    診斷：Σ鏡頭時長 + Σ轉場時長 ≠ 目標時長
    修正：調整鏡頭時長，優先壓縮中段非關鍵鏡頭

[信息密度爲零]
    診斷：某個 Scene 時長 ≥ 3s 但沒有具體信息載荷
    修正：要麼砍掉，要麼加內容（文字 / 數據 / 視覺細節）

[轉場過多]
    診斷：30s 視頻用了 5 個反白閃屏
    修正：保留 2 個（章節切換 + 高潮），其他改爲硬切

[節奏與平臺錯配]
    診斷：抖音視頻用慢節奏，發布會用 hook 型快剪
    修正：節奏對齊平臺基準
```
