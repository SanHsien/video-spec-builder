# 迭代模式工作流

[觸發條件]
    用戶在已有 video-spec.md 的項目裏提出修改 / 新增 / 調整 / 替換 / 風格變更。

[工作流]
    接住需求 → 判斷變更深度 → 按深度追問 → 衝突檢測 → 更新 spec → 告訴用戶

[頂層規則]
    - 無縫銜接，不開場白，不重新跑 Phase 1-5
    - 直接讀現有 spec，接住需求，按變更深度追問
    - 不打斷用戶工作流
    - 組合變更（一次包含多個層級）按最重的處理

---

## 重度變更

[觸發條件]
    涉及 Phase 1 必問項變更 / 整體節奏類型變更 / 受衆或核心信息變更。

[硬指標]
    能回答"這個變更怎麼影響整支視頻"——爲什麼改 / 影響哪些場景 / 整體節奏怎麼變 / 原素材還能用嗎 / 核心信息要不要跟着改。

[圍欄]
    - 不接受"全部重做"——這是 0-1 模式，應該歸檔舊 spec
    - 必須二次確認（先生成"預計改動總覽"讓用戶確認 OK 再動 spec 文件）

[完成後銜接文案]
    ✓ "改動總覽我先列出來——[受影響 Scene 列表 + 整體節奏變化 + 素材增刪]。你確認 OK 我再動 spec 文件。"

---

## 中度變更

[觸發條件]
    加新場景 / 刪場景 / 替換組件 / 大段重排。

[硬指標]
    能回答"具體改成什麼樣 + 與前後鏡頭怎麼銜接"——改哪個 Scene / 改成什麼組件 / 文案 / 時長 / 轉場要不要跟着改。

[圍欄]
    - 不允許悄悄改其他 Scene（只改用戶指定的）
    - 時長變了必須重新核對總時長與節奏檔位
    - 用戶卡住時給 2-3 個具體方案 + 優劣，不開放問

[完成後銜接文案]
    ✓ "Scene 3 換成 `aroll.timeline-card`，時長從 2s 拉到 3s，前一鏡頭轉場改成淡入。總時長 +1s。這樣改我去動文件。"

---

## 輕度變更

[觸發條件]
    調整旁白 / 屏顯文案 / 改 accent 色 / 改裝飾層 / 時長 ±0.5s 內。

[硬指標]
    確認理解正確——改什麼 / 改成什麼。

[圍欄]
    - 不優化用戶已確認的文案（除非明確要求）
    - 不改 markdown 結構

[完成後銜接文案]
    ✓ "accent 色從 #FF6A00 改成 #FF8C42，其他不動。"

---

## [衝突檢測]

加載現有 video-spec.md，新需求如果與現有內容衝突，必須直接指出 + 給方案讓用戶選。

[常見衝突類型]
    - 節奏衝突（總時長超 / 不夠）
    - 組件衝突（與已選場景類型組合不符）
    - 素材衝突（依賴的素材原 spec 沒有）
    - 轉場衝突（觸發硬規則，如反白閃屏 ≤ 2 次、Shader 轉場每 3 Scene ≤ 1 次）
    - 核心信息衝突（新內容稀釋 takeaway）

[停止追問的標準]
    - 能直接動手改 video-spec.md，不需要再猜或假設
    - 改完之後用戶不會說"不是這個意思"

---

## [更新文檔]

[紀律]
    - 在原 spec 上精確修改（不另存新文件）
    - 不改文檔 markdown 結構（標題層級 / 列表風格）
    - 不刪除用戶的注釋 / 備注
    - 改了分鏡表 → 用 `references/spec-rules.md` 的字段約束和 [交付前自檢清單] 重新核對
      （組件 ID 真實性 / 總時長誤差 / 反白閃屏額度 / 轉場字段齊全）

---

## [完成後告訴用戶]

    video-spec.md 已更新。
    - 改動總覽：[哪些 Scene / 總時長怎麼變 / 素材新增項]
    - 如果影響渲染，輸入 /hyperframes 重新生成視頻
