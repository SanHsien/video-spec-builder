[定位]
    這是追問紀律的約束工具，不是"靈感庫"，也不是問卷腳本。
    你默認走"創造性追問"路線，本題庫是約束基準——想接受敷衍時翻 [不接受的答案]，
    想提前結束時翻 [接受標準]，想瞎問時翻 [主問題]。

[紀律 · 用戶面前不暴露 Phase 標籤]

    Phase 1-5 是你內部的工作追蹤用語，**不是給用戶看的標籤**。
    維度章節名（如 [1.1 · 視頻目的]）也是你內部翻題庫用的，不要念給用戶聽。

    禁忌對用戶說：
    × "OK Phase 1 鎖定"
    × "進入 Phase 2"
    × "Phase 4 視覺微調"
    × "[追問深化] 觸發"
    × "[接受標準] gate 通過"
    × "我去開鎖 WebSearch 給你查"

    正確做法：用導演聊天的口語，**承上啓下**。
    一個話題聊完了，用一句"基本盤我懂了 / 素材清楚了"復述要點，
    然後自然引到下一個話題（"現在我們聊聊素材"、"接着聊聊視覺風格"）。
    具體過渡話術示例寫在每個 Phase 末尾的 [過渡話術示例] 裏。

[五段結構 · 每個維度都長這樣]

    [覆蓋意圖]      爲什麼問這個維度（防"問完不知道爲什麼問"）
    [主問題]        默認拋給用戶的問題（防"憑印象瞎問"）
    [追問深化]      用戶敷衍時的反擊話術，格式"用戶說 X → 你回 Y"（防"和氣接受敷衍"）
    [接受標準]      gate 通過條件（防"自我滿足提前停"）
    [不接受的答案]  必須駁回的答案樣本（防"編造合理答案"）

[漸進式追問]
    - Phase 1 是 gate，必須全部有答案，但答案可以從用戶初始描述抽取並復述確認
    - 用戶答某問題時"溢出"覆蓋了下一問題 → 直接吸收，不要再問
    - Phase 2-5 根據 Phase 1 答案動態裁剪（產品演示重點問 3D + UI mock，
      不問"3D 場景型"這種與產品演示不相關的維度）

[Phase 1 · 視頻基本盤]
    Phase 1 是地基。地基塌了，後面 4 個 Phase 全是流沙。這些維度必須全部問到具體答案，不允許跳過。

    [1.1 · 視頻目的]
        [覆蓋意圖]
            沒有目的的視頻是給自己看的日記。目的決定整片的取舍——
            沒有這條 gate，後面所有判斷都沒參考系。

        [主問題]
            - 這個視頻要解決什麼問題？讓看的人記住什麼？做什麼？
            - 這是科普 / 營銷 / 教學 / 產品演示 / 品牌 / 紀錄 哪一類？混合的不算，挑主導。
            - 看完之後用戶應該有什麼具體行動？點鏈接？記住一個概念？分享轉發？下載？注冊？

        [追問深化]
            - 用戶說"想火"→ 你回："火的標準是什麼？播放量、點贊數、轉化率、還是行業討論度？給我一個數字。"
            - 用戶說"科普 + 營銷"→ 你回："挑一個主導。如果只能保留一個目的，你保留哪個？另一個砍掉視頻就不成立嗎？"
            - 用戶說"讓大家學到東西"→ 你回："學到什麼具體的東西？一個名詞的定義？一個步驟的方法？一個判斷的標準？說一個。"
            - 用戶說"提升品牌認知"→ 你回："提升後用戶怎麼用腳投票？搜你的品牌名？復訪你的官網？提到品牌名時態度變了？"
            - 用戶說"做內容沉澱"→ 你回："沉澱給誰看？投資人？候選人？老用戶？新用戶？這三種人想看的東西完全不一樣。"
            - 用戶說"先做了再說"→ 你回："做了之後用什麼標準判斷它成功還是失敗？沒標準就別做。"

        [接受標準]
            - 一句話能說清楚"是什麼類型 + 讓誰記住什麼 + 看完去做什麼"
            - 例如：這是產品演示視頻，讓 SaaS 團隊的產品經理記住"我們的 AI 自動寫 PRD"，看完去官網注冊免費試用
            - 例如：這是品牌紀錄片，讓設計圈記住"我們的創始人是從工業設計轉 AI 的"，看完願意把視頻轉發到同行羣

        [不接受的答案]
            - "都行 / 看你的 / 沒想好" → 繼續追問
            - "想火 / 想出圈 / 高大上 / 顯得專業" → 這是結果不是目的，追問背後的具體目標
            - "做內容矩陣" / "爲了內容沉澱" → 沒有具體看的人就不叫沉澱，叫自嗨
            - "營銷 + 品牌 + 科普" 三合一 → 砍到一個，混合的不算

    [1.2 · 目標受衆]
        [覆蓋意圖]
            "給所有人看"等於"沒人會看"。受衆畫像決定旁白用語、信息密度、節奏速度——
            沒有這條 gate，所有表達決策都沒收斂方向。

        [主問題]
            - 畫一個具體的人。年齡、職業、城市、什麼時候看這個視頻？
            - 爲什麼會看？是被廣告投到了？是朋友轉的？是搜什麼搜到的？是從哪個賬號刷到的？
            - 他看過類似的內容嗎？看過的話，是什麼風格？看完什麼感覺？

        [追問深化]
            - 用戶說"年輕人"→ 你回："18 歲的實習生和 32 歲的產品經理都是年輕人，差 14 歲。挑一個。"
            - 用戶說"所有人"→ 你回："所有人 = 沒有人。一支視頻在某個具體場景給某個具體的人看。說一個場景一個人。"
            - 用戶說"懂技術的人"→ 你回："懂到什麼程度？看到 transformer 不用解釋？看到 attention 需要解釋？說一個具體標準。"
            - 用戶說"B 端客戶"→ 你回："什麼角色的 B 端客戶？決策者(CXO)、用戶(一線員工)、採購(IT)？這三種人關心的點不一樣。"
            - 用戶說"投資人 + 用戶 + 內部團隊都看"→ 你回："這三種人想看的視頻是三支不同的視頻。挑一個主受衆，其他兩個看就看不看就拉倒。"
            - 用戶說"我也不知道誰會看"→ 你回："那做什麼？沒有目標受衆的視頻是給自己看的日記，不是給別人看的內容。"

        [接受標準]
            - 能說清楚一個具體畫像：年齡段 / 職業 / 行業 / 看視頻的場景 / 看視頻前他在想什麼 / 看完會有什麼感覺
            - 例如：32 歲產品經理，在 SaaS 公司，刷小紅書時看到的，平時被產品 PRD 編寫折磨，看完想：原來 AI 能幫我寫 PRD，去試試

        [不接受的答案]
            - "所有人 / 任何想了解的人" → 沒有目標 = 沒有視頻
            - "懂行的 / 不懂行的" → 這是光譜，不是答案
            - "看個人喜好" → 那你爲什麼要做這支視頻？

    [1.3 · 平臺與時長]
        [覆蓋意圖]
            不同平臺的硬約束(豎橫屏、時長上限、靜音率)完全不同。
            不先定平臺和時長，所有節奏、文字大小、字幕策略都沒法落地。

        [主問題]
            - 主投放平臺是哪個？抖音、小紅書、B 站、視頻號、YouTube、Twitter/X、LinkedIn、官網首頁、產品頁內嵌、銷售 Deck？
            - 時長上限是多少？硬上限（平臺限制）和軟上限（你願意的最長時長）。
            - 比例：16:9 橫屏、9:16 豎屏、1:1 方屏、其他？
            - 幀率：24 / 30 / 60？
            - 是否需要無聲播放友好（用戶默認靜音刷，靠字幕看懂）？

        [追問深化]
            - 用戶說"多平臺都發"→ 你回："主戰場是哪個？多平臺 = 你要做橫屏、豎屏、方屏三個版本，時長和敘事節奏都不一樣。先挑主戰場。"
            - 用戶說"時長不限"→ 你回："B 站可以發 10 分鍾，抖音 1 分鍾就刷走了。'不限'意味着你沒想清楚。給我一個上限。"
            - 用戶說"看效果定"→ 你回："你的渲染參數 fps 都沒定，怎麼開始做？30fps 還是 60fps？60fps 渲染時間翻倍。"
            - 用戶說"豎屏"→ 你回："豎屏意味着大字海報、關鍵詞高亮、畫面中央留 70% 高度避開 UI 遮擋。你接受這套約束嗎？"
            - 用戶說"15 秒"→ 你回："15 秒能放 4-6 個 hook 節奏的鏡頭，每個 2-3 秒。這是抖音爆款節奏。你的內容塞得下嗎？"
            - 用戶說"3 分鍾左右"→ 你回："精確點。180 秒 vs 200 秒 vs 240 秒，這是三種敘事密度。挑一個。"

        [接受標準]
            - 知道：主平臺 / 時長（精確到 5 秒粒度）/ 比例 / 幀率 / 是否需要無聲友好
            - 例如：主投小紅書，豎屏 9:16，60 秒，30fps，無聲播放友好（必須有逐詞字幕）

        [不接受的答案]
            - "都發 / 多平臺" → 挑主戰場
            - "不限 / 看效果" → 不行
            - "默認就好" → 哪個默認？平臺默認還是你默認？說清楚

    [1.4 · 核心信息]
        [覆蓋意圖]
            防止視頻做完用戶說"看完不知道想說什麼"——一句話 takeaway 是整片的錨點。

        [主問題]
            - 用一句話說清楚：看完這支視頻，用戶應該記住什麼？
            - 砍到 12 字以內。多餘的字都是廢話。
            - 這句話是 hook 還是收尾？還是從頭貫穿到尾？

        [追問深化]
            - 用戶說"我們的產品很厲害"→ 你回："厲害是結果不是信息。說一個具體能力：寫 PRD？改圖？分析數據？說一個。"
            - 用戶說"AI 讓設計更簡單"→ 你回："讓誰的設計更簡單？怎麼簡單？省了什麼步驟？給一個對比。"
            - 用戶寫了 30 個字→ 你回："砍到 12 字。砍掉哪些字視頻還成立？砍掉哪些字視頻就垮？"
            - 用戶說"我們的核心理念是 XX"→ 你回："理念是抽象的，轉化成一個能被打印在 T 恤上的口號。一句話。"
            - 用戶給了三句話→ 你回："三句話 = 三個視頻。挑一個，另兩句話出現在腳本裏但不是主信息。"
            - 用戶說"我沒法用一句話講完"→ 你回："講不完意味着信息沒收斂。一支視頻只能傳遞一個核心信息，其他的都是支撐。"

        [接受標準]
            - 一句 12 字以內的核心信息
            - 這句話能被剪成大字海報的標題
            - 例如："AI 讓你 10 分鍾寫完 PRD" / "我們重新發明了 SaaS 計費" / "設計稿一鍵變前端代碼"

        [不接受的答案]
            - "我們的願景是改變世界" → 太空，砍到具體
            - 超過 12 字 → 砍
            - "看完用戶自己理解" → 你都不願意寫一句，憑什麼用戶花 60 秒看？

    [1.5 · 信息密度]
        [覆蓋意圖]
            節奏密度決定腳本字數、鏡頭數量、素材規模。
            不先定密度，後面的素材盤點和腳本編寫都沒參考線。

        [主問題]
            - 這支視頻的節奏是哪種？
                1. **Hook 型**（0.8-2s 一刀）：抖音爆款節奏，每秒都有新信息，靠節奏拉住人
                2. **教程型**（2-5s 一刀）：解釋清楚每個步驟，給觀衆反應時間，能跟着學
                3. **紀錄型**（3-8s 一刀）：讓畫面呼吸，有留白，有情緒鋪墊
            - 節奏密度和時長反推：60 秒 hook 型 = 30-60 個鏡頭；3 分鍾教程型 = 36-90 個鏡頭。你的素材撐得住嗎？

        [追問深化]
            - 用戶說"快節奏"→ 你回："0.8s 一刀還是 1.5s 一刀？這是兩種快。每個鏡頭你有內容塞進去嗎？"
            - 用戶說"看起來高級一點"→ 你回："高級 = 慢 + 留白 + 大字。但慢節奏要求每一幀都禁得住看。你的素材禁得住嗎？"
            - 用戶說"卡點剪輯"→ 你回："卡 BPM 的鼓點還是卡旁白的重音？這是兩套時間碼。說清楚。"
            - 用戶說"中等節奏就行"→ 你回："中等是托詞。說一個數字：平均每個鏡頭多少秒？2 秒 vs 3.5 秒 vs 5 秒，是三種感覺。"
            - 用戶說"先做着看"→ 你回："節奏決定腳本字數。60 秒 hook 型只能塞 90-130 個字旁白。你腳本寫完沒？"

        [接受標準]
            - 選定 hook / 教程 / 紀錄 中的一種主節奏
            - 知道大概的鏡頭時長（精確到 0.5 秒粒度）
            - 例如：hook 型 + 平均 1.5s 一鏡頭，60 秒視頻約 40 鏡頭

        [不接受的答案]
            - "看着辦 / 中等 / 看素材定" → 現在就定，節奏決定腳本字數
            - "再快一點 / 再慢一點" → 這是相對詞，給絕對值

    [1.6 · 品牌 Tone of Voice]
        [覆蓋意圖]
            沒有 Tone 錨點的視頻，旁白和文案會顯得沒人格，"機器味重"。

        [主問題]
            視頻的"氣質"是什麼？嚴肅 / 幽默 / 自嘲 / 權威 / 反諷 / 冷靜 / 熱烈？
            挑 1-2 個主導 + 1 個絕對不要的反向。

        [追問深化]
            - 用戶說"專業"→ 你回："專業有很多種。是 TED 講者那種'溫和權威'，還是 Apple Keynote 那種'神聖感'，還是麥肯錫那種'數據冷靜'？"
            - 用戶說"幽默"→ 你回："你是想讓人會心一笑，還是哈哈大笑，還是冷笑？幽默的顆粒度差別很大。"
            - 用戶說"年輕有活力"→ 你回："這是結果不是 Tone。具體是抖音網感、B 站二次元、還是 Z 世代反諷？"

        [接受標準]
            能用 1-2 個具體的"參考形象"錨定 Tone（如"TED 講者 + 一點 Karpathy 的自嘲"）

        [不接受的答案]
            - "專業 / 高大上 / 年輕 / 有活力" → 這些是結果不是 Tone
            - "看你的" → 必須用戶自己定

    [1.7 · 觀衆熟悉度]
        [覆蓋意圖]
            默認懂行話的視頻，給小白看就勸退；
            默認講基礎的視頻，給行內看就 boring。
            必須先定 onboarding 深度。

        [主問題]
            目標觀衆對話題的熟悉度是什麼？
            - 完全小白（要從"這是什麼"開始講）
            - 聽說過但不懂細節（要從"爲什麼重要"開始講）
            - 行內人（直接講"有什麼新東西"，不解釋術語）

        [追問深化]
            - 用戶說"普通人"→ 你回："普通人也分。地鐵裏刷視頻的普通人 vs 產品頁主動搜索的普通人，熟悉度完全不一樣。"
            - 用戶說"懂技術的人"→ 你回："懂到什麼程度？知道 RAG 是什麼嗎？知道 cosine similarity 嗎？知道 reranker 嗎？測試用戶的知識下限。"

        [接受標準]
            能說出"用戶 100% 懂的術語清單 + 100% 不懂的術語清單"的邊界

        [不接受的答案]
            - "都看得懂" → 不可能
            - "我猜他們應該懂" → 猜不算

    [過渡話術示例 · 聊完基本盤 → 開始聊素材]
        本段維度收完後，用承上啓下口語復述要點，自然引到素材話題。
        不要用"切換到下一階段"、"Phase 1 鎖定"、"進入 Phase 2"這種話。

        ✓ "好，你這視頻的基本盤我懂了——[復述目的/受衆/平臺/時長/核心信息中關鍵的幾條]。現在我們看看你手頭有什麼素材。"

[Phase 2 · 素材盤點]
    逐項盤問已有素材——用戶沒主動提的必須挨個問，否則就是憑空捏造內容。

    [2.1 · 內容素材]
        [覆蓋意圖]
            腳本是視頻的代碼。沒有逐字稿和數據來源，必然瞎編數字、瞎造案例。
            "差不多"出現在視頻裏就是事故。

        [主問題]
            - 旁白腳本有完整版嗎？大綱？賣點列表？還是只有一個想法？
            - 視頻裏要出現的具體數字、數據、案例、引用 —— 都有嗎？來源是什麼？
            - 用戶證言、客戶 logo、獲獎證書、媒體報道引用 —— 這些"信任錨點"素材有嗎？

        [追問深化]
            - 用戶說"我有大概的腳本"→ 你回："大概 = 沒有。逐字稿發我，或者我們現在寫。腳本是視頻的代碼，沒有腳本你就在拼樂高沒有圖紙。"
            - 用戶說"數字大概是 XX%"→ 你回："XX% 還是 XX.5%？數據出現在視頻上一旦錯了，就是事故。來源在哪？"
            - 用戶說"我現場再想"→ 你回："現場想 = 你願意接受 AI 自由發揮然後你回爐重做。要麼現在寫要麼接受 AI 寫完你審。"
            - 用戶說"賣點很多"→ 你回："列出來，按優先級排序。前 3 個出現在視頻裏，剩下的砍掉。"
            - 用戶說"我們的客戶有 XX、YY、ZZ"→ 你回："有 logo 授權嗎？沒授權的 logo 不能放，那一幀就是法務風險。"

        [接受標準]
            - 有完整旁白逐字稿（或確認讓你寫腳本後人工審）
            - 視頻中出現的所有數字 / 數據有來源
            - 已確認要出現的客戶 logo / 案例都有使用權

        [不接受的答案]
            - "大概" / "差不多就那個意思" → 視頻上不能差不多
            - "你幫我編一下" → 編可以，但你必須審，AI 編出來的數字你不審就上線是事故

    [2.2 · 音頻素材]
        [覆蓋意圖]
            旁白來源（真人 / TTS / 無）直接決定整片制作流程和時間表。
            BGM 節奏決定剪輯卡點。不先定音頻路徑，所有時間碼都沒基準。

        [主問題]
            先告知能力："渲染端內置本地 TTS（不需要 API key、不要錢、純本地。具體型號 / 支持聲音 ID / 支持語言數 → 我去查渲染端文檔或上網搜一下最新版本。)"
            然後問：
            - 旁白怎麼搞？三個選項：
                1. **真人錄音**（你或同事錄，發我 wav/mp3）
                2. **本地 TTS**（直接走配置）
                3. **不要旁白**（純文字 + 音樂）
            - 背景音樂打算用版權音樂（Epidemic Sound / Artlist）還是免版稅（YouTube Audio Library）？還是不要？
            - 音效（whoosh、click、ding）打算放嗎？

        [追問深化]
            **(a) TTS 路徑**
                - 用戶說"用 AI 配音"→ 你回："什麼語言？具體可用的聲音 ID 我去查渲染端文檔（或上網拉最新列表）。選一個或我列候選給你試。"
                - 用戶說"中文配音"→ 你回："本地 TTS 中文整體不如英文自然（中文 TTS 普遍如此）。介意嗎？介意就考慮真人錄音 + 後期混音。"
                - 用戶說"用 GPT 那種 voice"→ 你回："本地 TTS 不要 API key 不要錢不發出網絡請求。要做幾十次迭代用本地 TTS 不心疼，要做一次但音質極致可以考慮 ElevenLabs / 類似雲 TTS，但要單獨接入。挑一個路線。"
                - 用戶說"語速正常"→ 你回："本地 TTS 默認 1.0，教程類一般 0.7-0.8，營銷類 1.1-1.2。你這支是哪種？"

            **(b) 真人錄音路徑**
                - 用戶說"我錄"→ 你回："錄音環境是房間還是錄音棚？房間有反響音的話需要後期降噪。"
                - 用戶說"我自己錄中文"→ 你回："錄完發 wav 不要 mp3，無損方便調音。"
                - 用戶說"找配音演員"→ 你回："已經找好了？沒找好的話，從找配音到錄完到交付通常 3-7 天，先確認時間夠不夠。"

            **(c) 背景音樂**
                - 用戶說"用一首激勵向的音樂"→ 你回："激勵 = 多少 BPM？120 還是 140？決定剪輯卡點節奏。"
                - 用戶說"你幫我選"→ 你回："我可以從 Epidemic Sound 推薦 3 首，但你要有賬號能下載。有嗎？沒有就用 YouTube Audio Library。"
                - 用戶說"不要背景音樂"→ 你回："純人聲 + 環境音也行，但要確認旁白音頻本身夠幹淨。再說一次：要有節奏感的視頻，沒 BGM 會顯得很赤裸。"

        [接受標準]
            - 旁白路徑確定：真人 / TTS（帶聲音 ID，具體 ID 由渲染端文檔定）/ 無旁白
            - BGM 來源確定（具體歌曲或確認讓你推薦）
            - 是否要音效確定

        [不接受的答案]
            - "默認就行" → 哪個默認？
            - "等我錄完再說" → 那等你錄完再做視頻，現在先停

    [2.3 · 視頻 / 影像素材]
        [覆蓋意圖]
            真人出鏡 / B-roll / Lottie 是三類截然不同的影像素材，
            每類有不同的版權、摳像、循環規則。漏問任何一類後期都要回爐。

        [主問題]
            先告知能力："可用 u2net 本地摳像生成 VP9 alpha WebM，做'文字在人後面'這種透明疊加效果（text-behind-subject），一行命令搞定，不用綠幕。"
            然後問：
            - 有真人出鏡的素材嗎？（你自己講解、客戶證言、Vlog 風格、演示操作）
            - 有 B-roll 素材嗎？（產品鏡頭、工作場景、城市、自然畫面）這些是版權素材（Pexels / Pond5 / 自己拍）還是要從素材庫找？
            - 有現有的 Lottie 動畫文件（.json）嗎？

        [追問深化]
            **(a) 真人出鏡**
                - 用戶說"我有一段我自己講解的視頻"→ 你回："幾分鍾？分辨率？需要摳像放進視頻裏還是直接全屏放？需要摳像的話，背景是單色（綠幕/白牆）還是雜亂場景？u2net 對雜亂場景也行但邊緣可能有鋸齒。"
                - 用戶說"用客戶證言"→ 你回："客戶授權了嗎？時長多少？需不需要打字幕？需要的話我們後面用 transcribe 自動生成。"
                - 用戶說"我想做'文字穿過人後面'那種效果"→ 你回："OK，用 remove-background 生成兩層：cutout（人物前景透明）+ plate（背景透明，人物位置挖空）。中間夾文字。原視頻不能有快速移動否則邊緣穿幫。介意嗎？"

            **(b) B-roll**
                - 用戶說"用一些科技感的素材"→ 你回："科技感是 dystopia 那種霓虹？硅谷極簡？還是 NASA 控制臺？三種完全不同。"
                - 用戶說"我去 Pexels 找"→ 你回："找好了再說。Pexels 的素材有時和你想的差很遠，先找完再敲定節奏。"
                - 用戶說"我沒有 B-roll"→ 你回："那這支視頻就是純文字 + 數據 + 圖表了。可以做，但視覺就靠版式和動效撐。能接受嗎？"

            **(c) Lottie**
                - 用戶說"有 Lottie"→ 你回："幾個？分別是什麼動畫？時長多少？要循環播放還是單次？不允許 repeat: -1，循環要算 Math.ceil(duration / cycleDuration) - 1 的次數。"
                - 用戶說"沒有 Lottie 但想用"→ 你回："做 Lottie 要 After Effects + Bodymovin，這是單獨工作流。這次時間夠嗎？不夠就改用 CSS/GSAP 動畫。"

        [接受標準]
            - 真人出鏡素材列表：文件名 / 時長 / 分辨率 / 是否摳像
            - B-roll 素材列表：來源 / 數量 / 時長 / 是否已下載
            - Lottie 文件列表：路徑 / 時長 / 循環規則

        [不接受的答案]
            - "我有一些素材" → 列出來
            - "等我去找" → 找完再開工，否則就是憑空編

            - 有照片素材嗎？產品照、團隊照、場景照。

            - 字體文件清單：.woff2 路徑 + 字重列表

    [2.5 · 3D 資產 & 特殊視覺]
        [覆蓋意圖]
            3D / Shader / 音頻反應是"能力推銷項"，用戶不知道能做什麼就不會主動要。
            漏問 = 視覺表達手段被人爲縮減一半。

        [主問題]
            先告知能力：
            - 有 3D 模型嗎？GLTF / GLB 格式可以直接用，Three.js 加載。
            - 需要 HDRI 環境貼圖（讓 3D 物體有真實反射）嗎？
            - 想要 Three.js 程序生成的幾何體（粒子系統、wireframe、變形球）嗎？
            - 想要 Shader 轉場（WebGL 的高級轉場，比 CSS 轉場更有質感）嗎？
            - 想要音頻反應可視化（音頻頻譜驅動的圖形動畫）嗎？有現成 audio-reactive 參考支持。

        [追問深化]
            **(a) 3D**
                - 用戶說"用 3D 模型"→ 你回："模型來源？Blender 導出？買的？開源（Sketchfab CC 協議）？有版權嗎？"
                - 用戶說"做粒子效果"→ 你回："粒子是裝飾還是敘事？裝飾（背景閃爍）用 Canvas 2D 就夠，敘事（粒子組合成 Logo）需要 Three.js + 自定義着色器，工作量差 10 倍。"
                - 用戶說"做 wireframe 風格"→ 你回："wireframe 是裝飾背景還是某個 scene 的主角？如果是主角，要不要旋轉？要旋轉的話 RPM 多少？慢轉 6 秒一圈還是快轉 1 秒一圈？"

            **(b) Shader 轉場**
                - 用戶說"我要那種高級轉場"→ 你回："Shader 轉場是 GLSL 寫的，有現成的 shader-transitions 包。常見的有 dissolve、warp、glitch、wave。你想要哪種感覺？粗暴爆裂 vs 柔和過渡？"
                - 用戶說"看你的"→ 你回："我可以給 3 個 shader 備選，但每個 shader 是一種情緒。我給你預渲染 demo 你選。接受這種節奏嗎？"

            **(c) 音頻反應**
                - 用戶說"要那種音樂律動的效果"→ 你回："對哪個音頻做反應？BGM 還是旁白？反應在哪個元素上？字體粗細？光暈大小？卡片縮放？說一個。"
                - 用戶說"看着辦"→ 你回："對 BGM 節拍做反應最常見。元素是 hero 大字的 letter-spacing 或者背景圓環的半徑。你接受這個默認嗎？"

        [接受標準]
            - 是否需要 3D / Shader / 音頻反應可視化，明確 yes/no
            - 如果 yes，每一項都有具體描述

        [不接受的答案]
            - "高級一點" / "酷一點" → 砍到具體效果
            - "看你的" → 給方案讓用戶選，不要替用戶決定

    [2.6 · 待搜索素材]

        [告知能力]
            "免費商用素材主要從這些平臺搜：
            - 視頻 B-roll：Pixabay / Pexels / Mixkit / Coverr（大多 CC0）

            - 音樂 BGM：Pixabay Music / YouTube Audio Library / Uppbeat

            - 字體：Google Fonts / Adobe Fonts
            - 圖標：Lucide / Heroicons / Feather Icons / Phosphor
            - 插畫：Open Peeps / unDraw / Storyset

            - Lottie：LottieFiles"

        [追問深化]

            - 用戶沒 BGM → 你回："要 AI 幫你從 Pixabay Music 找一段 ___ 風格的 BGM 嗎？"
            - 用戶沒 B-roll → 你回："要從 Pexels / Mixkit 搜 ___ 主題的素材嗎？"
            - 用戶沒圖片 → 你回："要從 Unsplash 搜 ___ 風格的圖片嗎？"
            - 用戶沒音效 → 你回："要從 Freesound 搜 ___ 類型的音效嗎？"
            - 用戶沒插畫 → 你回："要從 unDraw / Storyset 搜 ___ 風格的插畫嗎？"
            - 用戶沒圖標 → 你回："默認用 Lucide 圖標庫（內置），還是要自定義？"
            - 用戶沒 3D 模型 → 你回："要從 Sketchfab / Poly Pizza 搜 ___ 模型嗎？注意篩選 CC 協議。"

        [每條搜索需求要寫齊 4 個字段]
            1. **源平臺**（Pixabay / Pexels / Unsplash / Freesound / ...）
            2. **關鍵詞**（具體英文/中文搜索詞，你幫翻譯優化）


            - 用戶給模糊描述（"溫暖的早晨"）→ 翻譯爲具體素材關鍵詞（"morning sunrise warm light"）
            - 用戶說"你看着辦" → 不允許，必須用戶拍板每條搜索需求的用途
            - 用戶給"好看的圖片" → 必須翻譯爲具體關鍵詞 + 風格描述

        [接受標準]
            每條待搜素材都有 4 字段（源平臺 / 關鍵詞 / 用途 / 驗收標準）

        [不接受的答案]
            - "隨便找幾個" → 必須明確用途
            - "好看的圖片" → 必須翻譯爲具體關鍵詞

    [過渡話術示例 · 盤完素材 → 開始聊表達手段]

        禁忌：

[Phase 3 · 表達手段激發]
    主動推銷可用能力。先告訴用戶"這個能力是什麼、能做什麼、不能做什麼"，再問"你要不要"。
    不要讓用戶回答自己不知道的東西。

    [3.1 · 場景類型組合]
        [覆蓋意圖]
            場景類型決定每個時間段的視覺語言。
            不先定組合，會拼成"什麼都有但什麼都不主導"的雜燴。

        [主問題]
            先告知能力："擅長以下 8 種場景類型，多選（你的視頻可能 60 秒裏組合 3-5 種）："

                1. **大字海報型**：屏幕大字 + 極簡留白。用於 hook、收尾、強調金句。字號由主題 display 檔位決定。
                2. **數據驅動型**：數字、圖表、對比、增長曲線。數字對齊由主題等寬設置處理。
                3. **流程圖解型**：箭頭、步驟、連接線。SVG path 繪制 + GSAP 時間軸。
                4. **結構圖解型**：層級、關系、架構圖。用 grid + hairline 邊框。
                5. **UI 演示型**：產品截圖、點擊軌跡、狀態變化。可以是真截圖或 mock 復刻。
                6. **抽象概念型**：粒子、wireframe、變形、隱喻。Three.js 或 Canvas 2D。
                7. **真人出鏡型**：talking head、摳像、文字穿人後面。u2net 摳像。
                8. **3D 場景型**：3D 模型旋轉、剖切、解構。Three.js + GLTF。

            你的視頻裏會出現哪幾種？按出現順序列。

        [追問深化]
            - 用戶說"全要"→ 你回："60 秒視頻裏塞 8 種場景類型 = 每種 7.5 秒。這種密度只有 hook 型短視頻能撐住，3 分鍾視頻塞 8 種會失焦。砍到 3-5 種。"
            - 用戶說"主要是大字海報"→ 你回："純大字海報視頻要麼很猛要麼很瘟。猛是節奏快 + 字體變形 + 反白閃屏；瘟是字大但鏡頭不動 8 秒。你哪種？"
            - 用戶說"要數據驅動"→ 你回："數據的來源準備好了？數據可視化裏數字必須出現在屏幕上，不準確就是事故。"
            - 用戶說"UI 演示"→ 你回："UI 用真截圖還是 mock 復刻？真截圖分辨率夠嗎？mock 復刻你提供設計稿還是用 components-catalog 拼？"
            - 用戶說"抽象概念"→ 你回："抽象到什麼程度？粒子飄動（裝飾）vs 粒子組成數據（敘事）。"
            - 用戶說"3D 場景"→ 你回："3D 是 1 個鏡頭還是貫穿全片？1 個鏡頭可以做，全片 3D 渲染時間和復雜度直線上升。"

        [接受標準]
            - 列出 3-5 個場景類型，按出現順序排
            - 例如：[大字海報型(hook + 收尾)]→[數據驅動型]→[流程圖解型]→[UI 演示型]→[大字海報型]

        [不接受的答案]
            - "全要 / 看你的 / 都可以" → 砍

    [3.2 · 文字呈現方式]
        [覆蓋意圖]
            字幕樣式直接決定信息密度和靜音可讀性。
            社媒短視頻不用逐詞字幕，70% 靜音用戶看不懂在說什麼。

        [主問題]
            先告知能力："字幕能力有三檔（旁白時間軸決定）："

                1. **常駐字幕**：全句出現，停留幾秒，下一句替換。最樸素。
                2. **關鍵詞高亮**：全句出現，某個關鍵詞顏色加粗或加 marker / 圈圈 / burst / scribble。
                3. **卡拉 OK 逐詞**：本地 Whisper 自動生成逐詞時間戳，每個詞在被念到的瞬間高亮（顏色變 / 字重變 / 微縮放）。

            然後問：
            - 你要哪一檔？社媒短視頻幾乎必選 3，教程片常選 1 或 2，紀錄片常選 1。
            - 關鍵詞強調用什麼形式？marker（亮色矩形掃過）/ 手繪圈（SVG 圓圈逐漸畫出）/ burst（爆炸放射線）/ scribble（塗鴉曲線下劃線）/ sketchout（手繪劃掉線表示否定）。
            - 還有打字機效果（字一個一個跳出來）嗎？動態字重變化（字重從 400 漸變到 800 強調）嗎？

        [追問深化]
            - 用戶說"做小紅書的"→ 你回："幾乎一定要卡拉 OK 逐詞字幕，因爲 70% 用戶靜音刷。用本地 Whisper 直接生成時間戳，不要 API key。同意嗎？"
            - 用戶說"教程視頻"→ 你回："建議常駐字幕 + 關鍵詞高亮。每句話停留 2-4 秒，關鍵詞用 marker（亮色矩形掃過）強調。"
            - 用戶說"不要字幕"→ 你回："確定？平臺默認靜音播放的話，30%-70% 用戶看不懂在說什麼。再次確認。"
            - 用戶說"想要那種打字機"→ 你回："打字機效果在每個場景持續 2-3 秒就夠，太長用戶會煩。你要打字機的場景是 hook、定義、還是收尾？"
            - 用戶說"要 marker"→ 你回："marker 顏色用主題 accent 色（如品牌色覆蓋默認），跨越關鍵詞寬度做 sweep 動畫。OK 嗎？"

        [接受標準]
            - 字幕檔位確定（1/2/3）
            - 如果選 2，關鍵詞強調形式確定（marker / 圈 / burst / scribble / sketchout）
            - 是否要打字機、動態字重，明確 yes/no

        [不接受的答案]
            - "看你的字幕樣式" → 字幕樣式直接影響信息密度，必須用戶參與
            - "都要" → 選一種主力，其他偶爾點綴

    [3.3 · 動效語言]
        [覆蓋意圖]
            轉場密度和類型決定整片的"質感錨點"。
            不先定動效語言，每個 Scene 之間的過渡會亂拼，顯得廉價。

        [主問題]
            先告知能力："支持以下轉場類型——"
                1. **反白閃屏**（bg-flash 閃一幀，硅谷科技風經典）
                2. **CSS crossfade**（柔和淡入淡出）
                3. **CSS wipe**（橫向 / 縱向擦除）
                4. **Shader 轉場**（GLSL 着色器，dissolve / warp / glitch / wave，更有質感）

            然後問：
            - 轉場密度：硬切多（節奏快，類似 MTV）/ 轉場多（每個場景間都有過渡）？
            - 轉場是統一一種還是混用？混用的話怎麼分配？
            - 音頻反應可視化要嗎？（BGM 節拍驅動元素脈動 / 旁白音量驅動字體粗細）

        [追問深化]
            - 用戶說"轉場多"→ 你回："每個場景間都轉場？60 秒視頻如果 30 個場景，30 次轉場，每次平均 0.4-0.8 秒，那純轉場就佔 12-24 秒，剩餘內容時間只有 36-48 秒。你能接受嗎？"
            - 用戶說"用 shader 轉場"→ 你回："shader 轉場單次 0.6-1.2 秒。每個 shader 是一種情緒，混用會亂。建議全片用 1 種 shader（比如 dissolve），關鍵節點偶爾換。"
            - 用戶說"反白閃屏經典"→ 你回："反白閃屏單次 0.1-0.2 秒，是節奏性強調。一般用在 hook 進入或者大數據揭示前。頻率多了眼睛累。"
            - 用戶說"硬切多一些"→ 你回："硬切適合 hook 型短視頻，連續硬切讓節奏 punchy。但硬切之間的鏡頭如果同色調，會顯得混亂。你的鏡頭色調對比夠嗎？"
            - 用戶說"音頻反應"→ 你回："對哪段音頻？BGM 節拍最常見。可映射的屬性：大字字距微抖 / 背景圓環脈動 / 卡片輕微縮放。你選一種作爲主導，具體參數等下定。"

        [接受標準]
            - 轉場密度 + 主轉場類型 + 是否音頻反應，全部明確
            - 例如：轉場密度中等（每 4-5 個場景一次），主用 CSS crossfade，重點節點用 shader dissolve，反白閃屏用在 2 處大數據揭示

        [不接受的答案]
            - "酷一點 / 高級一點" → 給具體轉場名
            - "看你的" → 給 2-3 個方案讓用戶選

    [3.4 · 節奏基準]
        [覆蓋意圖]
            節奏檔位的具體參數（鏡頭數 / 字數）在 Phase 1.5 之後再精確化一遍，
            避免腳本字數和素材數對不上時長。

        [主問題]
            先告知能力："節奏決定腳本字數和鏡頭數量。推薦三檔："

                1. **Hook 型**：每個鏡頭 0.8-2 秒。60 秒視頻 ≈ 30-60 鏡頭。中文旁白約 90-130 字。
                2. **中等**：每個鏡頭 2-5 秒。3 分鍾視頻 ≈ 36-90 鏡頭。中文旁白約 400-550 字。
                3. **慢節奏**：每個鏡頭 3-8 秒。3 分鍾視頻 ≈ 22-60 鏡頭。中文旁白約 280-450 字。

            然後問：
            - 你選哪一檔？和前面說的信息密度保持一致。
            - 釘一個目標鏡頭數量。
            - 釘一個目標旁白字數。

        [追問深化]
            - 用戶說"節奏快但不要太快"→ 你回："1.5 秒一鏡頭還是 2.5 秒一鏡頭？這是兩種節奏。1.5 秒 = hook 型，2.5 秒 = 中等。挑一個。"
            - 用戶說"hook 型"→ 你回："60 秒視頻裏你要塞多少信息？hook 型每鏡頭只能傳 1 個信息點。60 秒 = 40 個鏡頭 = 40 個信息點。你的腳本有 40 個信息點嗎？"
            - 用戶說"按音樂節奏剪"→ 你回："音樂 BPM 多少？120 BPM = 每拍 0.5 秒，每兩拍 1 秒，每四拍 2 秒。你卡哪個？四拍 = 2 秒一刀，是中等節奏。"
            - 用戶說"開頭快後面慢"→ 你回："前 15 秒 hook 型，15 秒後轉中等？這種結構常見但要保證轉點自然。轉點設計了嗎？"
            - 用戶說"快慢交替"→ 你回："怎麼交替？2 快 1 慢 vs 3 快 2 慢？規律不清的話感覺會亂。"

        [接受標準]
            - 節奏檔位確定
            - 目標鏡頭數量精確到 5 鏡頭粒度
            - 目標旁白字數精確到 50 字粒度

        [不接受的答案]
            - "看素材定" → 節奏決定素材怎麼剪，必須先定
            - "靈活一點" → 靈活 = 沒想清楚

    [3.5 · 敘事節拍設計]
        [覆蓋意圖]
            沒有節拍設計的視頻是"線性平鋪"，留不住觀衆。
            必須明確 hook / 轉折 / 高潮 / cta 的位置。

        [主問題]
            視頻的節拍設計：
            - hook 在第幾秒？拋什麼鉤子？
            - 有沒有"屏息時刻"（讓觀衆喘一口氣）？
            - 高潮 / 反轉 / 揭曉在哪裏？
            - CTA 收在哪裏？

        [追問深化]
            - 用戶說"開頭直接講"→ 你回："講什麼？數據衝擊、反問、懸念、自嘲，四種 hook 路線，挑一個。"
            - 用戶說"沒想過節拍"→ 你回："用前面說的信息密度反推——hook 型必須有鉤子，紀錄型可以平鋪。你是哪種？"
            - 用戶說"全程高潮"→ 你回："全程高潮就是沒高潮。挑 1-2 個真正的爆點。"

        [接受標準]
            畫得出節拍曲線（X 軸時間 / Y 軸情緒強度）

        [不接受的答案]
            - "順其自然" → 視頻不是日記
            - "全程緊湊" → 這是密度不是節拍

    [3.6 · 情緒曲線]
        [覆蓋意圖]
            情緒沒有起伏的視頻是"平的"，看完沒記憶點。
            每個 Scene 都要服務於情緒曲線的某個位置。

        [主問題]
            視頻開頭 / 中段 / 收尾，分別想讓觀衆產生什麼情緒？
            起伏方向是什麼？（平→爆 / 爆→冷 / 冷→暖 / 暖→反思）

        [追問深化]
            - 用戶說"看完覺得我們牛逼"→ 你回："這是結論不是情緒。是震撼？敬意？信任？興奮？挑一個具體情緒。"
            - 用戶說"沒想過"→ 你回："反推一下——如果刪掉某個 Scene，情緒曲線斷在哪？用這個找每個 Scene 的情緒職責。"

        [接受標準]
            能用 3 個情緒詞分別描述開頭 / 中段 / 收尾（如"好奇 → 震撼 → 行動欲"）

        [不接受的答案]
            - "都行" → 情緒是設計不是偶然
            - "看完覺得值" → "值"不是情緒

    [3.7 · 音畫關系]
        [覆蓋意圖]
            BGM 和畫面同步 vs 錯位，是兩種完全不同的視頻語法。
            默認同步會顯得乏味（看到 X 聽到 X），錯位會顯得高級。

        [主問題]
            - BGM 是敘事性（推動情節進度）還是氛圍性（襯托情緒）？
            - 旁白節奏和畫面節奏同步還是錯開？
            - 是否要"音畫同步爆點"（鼓點+反白閃屏這種 hard cut）？

        [追問深化]
            - 用戶說"BGM 跟着畫面走"→ 你回："跟着畫面走就是從屬，BGM 沒存在感。要不要讓 BGM 獨立成線？"
            - 用戶說"不知道音畫關系"→ 你回："給三個反例自己挑——看到爆炸+聽到爆炸 = 廉價；看到爆炸+聽到悠揚鋼琴 = 高級；看到平靜+聽到鼓點 = 緊張。你想要哪種？"

        [接受標準]
            能說出至少 1 處"音畫錯位"的設計點（或明確選擇全程同步）

        [不接受的答案]
            - "BGM 配上就行" → 這是後期不是設計
            - "隨便" → 音畫關系決定視頻質感

    [過渡話術示例 · 聊完表達手段 → 選視覺主題]
        本段維度收完後，復述節奏/字幕/轉場的關鍵決定，自然引到主題選擇。

        ✓ "節奏和呈現方式都定了。最後挑個主題——8 個 HF 預設裏選，或者你自己上傳？"
        ✓ "OK 表達手段這塊清楚了——[復述：節奏幾秒一刀 / 字幕哪一檔 / 轉場什麼風格]。下一個事兒是視覺主題，我有 8 個預設你看看。"
        ✓ "好，節奏感和動效語言我心裏有譜了。現在挑主題——按你的內容方向我可以先推 2-3 個候選。"

        禁忌：
        × "Phase 3 鎖定，Phase 4 視覺微調"
        × "表達層 gate 通過，進入主題選擇"

    [4.1 · 主題選擇]
        [覆蓋意圖]
            主題是 token 鎖定的入口。不先選定主題，
            後面任何字號 / 間距 / 配色調整都沒基準。

        [主問題]
            視頻要長什麼樣？兩條路任選：

            路徑 1：8 個 HyperFrames 預設裏挑一個
            路徑 2：自己的自定義主題 —— 項目根目錄的一個 design.md

        [路徑 1 · 8 預設速覽]

            路徑基準 = video-spec.md 所在目錄）。不再有 styles/ 文件夾。

                你上網調研後給 2-3 個候選方案，定稿後在項目根生成 design.md

        [追問深化]
            - 用戶說"預設但不知道選哪個"→ 你回："你視頻的內容是什麼類型？我根據前面說的目的幫你匹配最貼的 2-3 個。"
            - 用戶說"自定義"→ 你回："已經有設計好的文件了嗎？有就上傳 / 粘貼；沒有就描述三個形容詞 + 給參考鏈接，我上網搜搜後出 2-3 個候選方案。"
            - 用戶說"隨便"→ 你回："這不是答案。給三個最常用的預設三選一：Swiss Pulse（數據冷靜）/ Data Drift（科技演示）/ Shadow Cut（嚴肅科幻）。挑一個。"

        [接受標準]
            用戶給出明確的 theme 選擇，能寫到 video-spec.md 的 theme 字段

        [不接受的答案]
            - "隨便 / 都行 / 你看着辦" → 必須用戶拍板
            - "想要高大上 / 炫酷 / 有質感" → 形容詞不算答案
            - "和 XX 一樣" → 不指明哪個具體決定，需追問到具體 hex / 字體名

    [4.2 · accent 色覆蓋]
        [覆蓋意圖]
            accent 色是品牌識別度的核心 token。
            不明確"保留主題默認 / 改爲品牌色"，視頻會被默認值"通用化"掉品牌特徵。

        [主問題]
            主題裏的 accent 用默認，還是換成你的品牌色？

        [追問深化]
            - 用戶說"換"→ 你回："給我 hex 值。'品牌橙' / '深藍色' 不接受。"
            - 用戶說"默認"→ 記下"用主題默認 accent"，不再追問
            - 用戶說"不知道"→ 你回："發 logo 鏈接，我幫你提取主色給你確認。"

        [接受標準]
            明確決定保持 / 覆蓋；覆蓋時有具體 hex 值

        [不接受的答案]
            - "差不多顏色就行" → 必須給 hex
            - "和 logo 一樣" → 必須用戶發 logo 讓你取色

    [4.3 · 裝飾層密度]
        [覆蓋意圖]
            裝飾過多蓋過信息，裝飾過少顯得空。
            必須明確檔位，否則會按個人審美自由發揮。

        [主問題]
            裝飾量：純淨 / 中等 / 強？
            - 純淨 = 只用主題原生裝飾
            - 中等 = 加 hairline / cross / 角標
            - 強 = 加 dot-pulse / scan-lines / 多層裝飾

        [追問深化]
            - 用戶說"看着辦"→ 你回："默認中等。如果你的視頻信息密度大（數據型/教程型），建議純淨；如果視頻偏氛圍（hook 型 / 品牌片），可以中等到強。"
            - 用戶說"越多越好"→ 你回："裝飾過多會蓋過信息密度，看完觀衆記住裝飾記不住內容。除非你做品牌氛圍片，否則建議中等。"

        [接受標準]
            三檔之一明確

        [不接受的答案]
            - "好看就行" → 給三檔讓用戶選
            - "你決定" → 給推薦 + 讓用戶拍板

    [4.4 · 組件白名單 / 黑名單]
        [覆蓋意圖]
            黑白名單是"風險隔離"機制——某些組件用戶明確不要（如圖表 / 卡通插畫），
            提前寫進 spec 可以避免誤用。

        [主問題]
            看過 components-catalog.md 後，有想用的 / 一定不要的組件嗎？

        [追問深化]
            - 用戶說"沒看過 catalog"→ 你回："先掃 3 個核心分類（aroll / broll-hero / broll-charts），10 分鍾看完。"
            - 用戶說"全都行"→ 默認白黑名單都爲空 = 全開
            - 用戶說"不要圖表"→ 你回："黑名單加 broll-charts.*，確認。"

        [接受標準]
            白名單 / 黑名單明確（可以都爲空 = 全開）

        [不接受的答案]
            - "我不知道有哪些組件" → 讓用戶先掃一眼 catalog，不允許跳過

    [過渡話術示例 · 主題定了 → 聊參考與反例]
        本段維度收完後，復述主題選擇，自然引到參考視頻/反例話題。

        ✓ "OK 主題挑好了。最後一步——你有看過類似的視頻參考嗎？或者哪種風格是絕對不要的？"
        ✓ "好，[復述：主題名 + accent 色 + 裝飾檔位] 都定了。剩最後一件事：發我 1-2 個參考視頻，再說說哪種感覺你最討厭。"

        禁忌：
        × "Phase 4 完成，進入 Phase 5"
        × "主題層 lock，開鎖參考層"

[Phase 5 · 參考與反例]
    Phase 5 是用具體作品定調，比抽象描述精確 10 倍。

    [5.1 · 參考視頻]
        [覆蓋意圖]
            沒有參考 = 你和用戶腦子裏各想各的。
            參考視頻是"對齊期待"的最高效方式。

        [主問題]
            - 發鏈接：YouTube、Vimeo、B 站、抖音、小紅書、Apple 發布會片段、Stripe 官網視頻、Linear 發布視頻，任何具體作品。
            - 這支視頻和參考"9 分像 1 分不一樣"，那 1 分不一樣的是什麼？

        [追問深化]
            - 用戶發了鏈接但說"全都像"→ 你回："全都像 = 抄。你這支視頻憑什麼獨立存在？至少給一個差異化的點。"
            - 用戶說"像 Apple 那種"→ 你回："Apple 的哪一支？iPhone 發布會的產品鏡頭？AirPods Max 的 motion graphics？M 系列芯片的剖切動畫？這是三種風格，挑一個。"
            - 用戶說"像 Linear / Stripe 那種產品視頻"→ 你回："Linear 和 Stripe 的視頻風格不一樣。Linear 是產品截圖 + 慢鏡頭 + 極簡文字；Stripe 是數據可視化 + 流暢過渡。挑一個。"
            - 用戶沒參考→ 你回："沒參考 = 你的腦子裏有一個想象但沒法對齊。強制找一個，哪怕不完全像。否則你和 AI 都在猜對方想要什麼。"
            - 用戶發了 5 個參考→ 你回："5 個參考之間衝突嗎？把它們貼在一起看一下，矛盾的地方你選哪個？"

        [接受標準]
            - 至少 1 個參考視頻 + 1 個差異化點
            - 例如："像 Linear 發布視頻，但我們配音是中文 + 數據更多 + 節奏更快"

        [不接受的答案]
            - "我腦子裏有個畫面但沒找到參考" → 強制找一個
            - "都不像 / 全新的風格" → 全新 = 沒基準 = 風險拉滿

    [5.2 · 靜態參考]
        [覆蓋意圖]
            靜態參考補充視頻參考無法對齊的視覺細節（版式 / 字體 / 裝飾）。
            少了這一層，主題 token 微調就靠"感覺"。

        [主問題]
            - 海報、Behance / Dribbble 作品、產品頁截圖、PPT 一頁、雜志版式 —— 任何靜態視覺參考。
            - 哪一點想要：版式？顏色？字體？裝飾？層次感？

        [追問深化]
            - 用戶發了 Behance 鏈接→ 你回："裏面 12 張圖，你看的是哪一張？發圖不是發鏈接。"
            - 用戶說"參考 Linear 官網首頁"→ 你回："首頁的 hero 區？feature 區？還是 pricing 區？截圖發我。"
            - 用戶說"雜志感"→ 你回："什麼雜志？Apartamento（極簡版式）vs Wired（信息密集）vs Kinfolk（留白多）。三種完全不一樣。"
            - 用戶說"產品頁好看的就行"→ 你回："Linear / Stripe / Vercel / Resend / Cursor / Raycast，這些都是產品頁好看的，但風格各異。挑一個。"

        [接受標準]
            - 至少 1-3 張具體參考圖（圖，不是鏈接）
            - 明確說出參考的具體點（版式 / 顏色 / 字體 / 裝飾 / 層次）

        [不接受的答案]
            - 只發鏈接不發圖 → 讓用戶截圖
            - "都好看" → 這不是答案

    [5.3 · 反例]
        [覆蓋意圖]
            反例是"邊界 fence"。用戶沒態度，就會按平均審美自由發揮，
            結果做出一個"標準但平庸"的視頻。

        [主問題]
            - 討厭的類似視頻是什麼？討厭的具體點？
            - 反向要求：絕對不能出現的元素 / 風格 / 表達方式。
            - 哪個友商的視頻你最不想被對比？

        [追問深化]
            - 用戶說"不要太花哨"→ 你回："花哨 = ？粒子？轉場密？顏色多？emoji？給一個具體反例。"
            - 用戶說"不要看起來 cheap"→ 你回："cheap 的標志是什麼？Times New Roman 字體？emoji？模板感動效？低分辨率截圖？"
            - 用戶說"不要像友商 XX"→ 你回："友商 XX 的視頻你具體討厭哪個點？版式？顏色？節奏？模仿？避開模仿那一點就行。"
            - 用戶說"沒什麼不想要的"→ 你回："那你就是沒態度。強制找一個反例：你刷到什麼樣的視頻會立刻劃走？"
            - 用戶說"不要 AI 味"→ 你回："AI 味 = 什麼？模板化轉場？無意義的粒子飄動？過度精致的漸變？說一個。"

        [接受標準]
            - 至少 1 個反例 + 至少 3 條"絕對不要"清單
            - 例如："討厭國內 SaaS 廠商視頻裏那種漸變 + 3D 圖標 + 卡通插畫的組合 / 不要用 emoji / 不要圓角太大 / 不要插畫風格"

        [不接受的答案]
            - "都行 / 沒什麼不要的" → 沒態度 = 自由發揮 = 你回爐重做風險拉滿

    [5.4 · 同質化反例]
        [覆蓋意圖]
            每個賽道都有"做爛了"的視覺套路。
            如果不主動避開，新視頻會立刻被觀衆歸類到"又一個 XX 類視頻"。

        [主問題]
            同類視頻做爛了什麼套路？哪些視覺 / 敘事 / 節奏要主動避開？

        [追問深化]
            - 用戶說"不知道做爛了什麼"→ 你回："列 3 個同類視頻發我，我幫你分析公共套路。"
            - 用戶說"我的視頻不一樣"→ 你回："不一樣在哪裏？具體到視覺 / 敘事 / 節奏 / 音樂。"
            - 用戶說"反正不要俗氣的"→ 你回："俗氣不是反例。具體——'不要黑紅配色 / 不要倒計時 / 不要男低音 voiceover'。給三條。"

        [接受標準]
            至少 3 個具體的"不要 XX"清單（視覺 / 敘事 / 節奏 / 音樂各一個）

        [不接受的答案]
            - "不要俗氣" → 不具體
            - "做出新意就行" → 結果不是反例

[追問紀律 · 8 條]

    1. 不憑印象瞎問 —— 問之前對照 [覆蓋意圖] 校準
    2. 不和氣接受敷衍 —— 用戶答"高大上 / 都行 / 隨便"時翻 [不接受的答案] 駁回
    3. 不自我滿足提前停 —— 對照 [接受標準] 檢查 gate
    4. 不編造用戶沒說的內容 —— 推斷 / 假設的內容標 [待用戶確認]
    5. 能力告知先於追問 —— 問能力前先解釋能做什麼，讓用戶在知情前提下選
    6. 主題選定後不重復問 token —— 選定後字體/字重/字號鎖定
    7. 素材逐項盤問 —— Phase 2 不能漏報
    8. 每 Phase 閉環復述 —— Phase 結尾把答案復述給用戶確認
